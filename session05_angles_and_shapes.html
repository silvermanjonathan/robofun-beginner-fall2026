Opener · 10 minutes

Retrieval: return, one week on

Paper first.

Question: What does a function hand back when it has no return line?

def show_double(n):
    print(n * 2)

def double(n):
    return n * 2

a = show_double(21)
b = double(21)
print(a)
print(b)
print(double(21) + 1)

None, which is Python's word for no value.

print and return do different jobs. print sends text to the terminal for a person to read, and hands nothing back to the code. return hands a value back to the line that called the function. That line can store it in a variable, use it in arithmetic, or pass it straight into another function.

In the code above, show_double(21) prints 42 and then a holds None. double(21) prints nothing and b holds 42. The last line works only because double returns a number; show_double(21) + 1 would crash, because None plus 1 is a TypeError.

Question: Write a function turn_size(sides) that hands back the angle you must turn at each corner to close a shape with sides sides, where sides is the number passed in as the argument.

def turn_size(sides):
    return 360 / sides

One line of arithmetic, 360 divided by the number of sides, handed back with return. Every shape drawn today closes because of this number.

Chunk 1 of 8

The rule behind every closed shape

A full turn is 360 degrees. Walking a closed shape means you finish facing the way you started, so all your turns have to add to exactly 360. Divide 360 by the number of corners and you have the turn for each one.

That is the function from the opener, so here it is typed in and used. The loop calls turn_size once per pass, keeps what it hands back under the name turn, and prints it. The call has to land somewhere: on its own line, with nothing to catch the value, it would run and throw the answer away.

def turn_size(sides):
    return 360 / sides

for sides in range(3, 9):
    turn = turn_size(sides)
    print(f"{sides} sides -> {turn} degrees per turn")

Predict: A triangle has three corners. Is the turn at each corner 60 degrees or 120?

4 sides -> 90.0 degrees per turn
5 sides -> 72.0 degrees per turn
6 sides -> 60.0 degrees per turn
7 sides -> 51.42857142857143 degrees per turn
8 sides -> 45.0 degrees per turn

120. The inside angle of an equilateral triangle is 60, but the turn you make walking around the outside is 120. This trips up nearly everyone once, and it is the reason we compute the turn rather than remember it.

Chunk 2 of 8

Where a step lands

Every spot in a window has two numbers, an x and a y. That is the same idea as a point on a coordinate grid in maths, with one difference: y counts down from the top, not up from the bottom. The corner (0, 0) is top left.

Which way you are facing is called your heading. It is an angle in degrees. 0 means facing right. Turning clockwise makes the number grow, so 90 faces straight down and 180 faces left.

A step means walking a set number of pixels in the direction you face. pygame.draw.line needs both ends of the line. You know the start and the heading, so the far end has to be worked out.

A diagonal step is part across and part down. math.cos tells you how much of the step is across, and math.sin tells you how much is down. You do not need to know how they work inside. You only need to know that they split a step into those two parts.

cos and sin measure angles in a unit called radians, not degrees. So math.radians converts first, the way you would convert inches to centimetres before using a metric ruler. The function then hands back both numbers at once, separated by a comma.

step_end takes four values, in this order: x and y, where the step starts; heading, which way it goes; and length, how far. In the four calls below, the start is always (100, 100) and the length is always 50. Only the heading changes, so any difference in the answers comes from the heading alone.

step_end(100, 100, 0, 50)
         x    y  heading length

x, y      where the step starts
heading   which way it goes
length    how far it goes

import math

def step_end(x, y, heading, length):
    end_x = x + length * math.cos(math.radians(heading))
    end_y = y + length * math.sin(math.radians(heading))
    return round(end_x, 1), round(end_y, 1)

print(f"heading 0   {step_end(100, 100, 0, 50)}")
print(f"heading 90  {step_end(100, 100, 90, 50)}")
print(f"heading 180 {step_end(100, 100, 180, 50)}")
print(f"heading 45  {step_end(100, 100, 45, 50)}")

Predict: A heading of 90 degrees. Does the step go up the screen or down it?

What it actually prints

heading 0   (150.0, 100.0)
heading 90  (100.0, 150.0)
heading 180 (50.0, 100.0)
heading 45  (135.4, 135.4)

Down. The second coordinate grows downward in a window, so a positive turn goes clockwise and a heading of 90 points at the floor. Leave out math.radians and nothing crashes: math.cos(90) is a real number, about negative 0.45, and your shape comes out as a scribble. That is a silent bug with no error message.

Chunk 3 of 8

A window you can draw on

This is the first program of the term that opens a window. The lines before the drawing set it up. set_mode opens a window 640 wide and 480 tall. canvas is a blank picture of the same size, kept in memory, and canvas.fill(BG) paints it one colour. Every colour here is three numbers: how much red, green, and blue, each from 0 to 255.

The drawing happens once, onto the canvas, above the loop. pygame.draw.line draws on the canvas, not on the window.

The loop at the bottom has one job: copy the canvas onto the window sixty times a second until you close the window. Copy the loop as it stands. Session 10 takes it apart line by line.

import math
import pygame

WIDTH = 640
HEIGHT = 480
BG = (27, 41, 81)
YELLOW = (252, 211, 77)

def step_end(x, y, heading, length):
    end_x = x + length * math.cos(math.radians(heading))
    end_y = y + length * math.sin(math.radians(heading))
    return end_x, end_y

pygame.init()
screen = pygame.display.set_mode((WIDTH, HEIGHT))
clock = pygame.time.Clock()
canvas = pygame.Surface((WIDTH, HEIGHT))
canvas.fill(BG)

# ---- your drawing, done once ----
end_x, end_y = step_end(100, 100, 30, 200)
print(f"line runs from (100, 100) to ({round(end_x, 1)}, {round(end_y, 1)})")
pygame.draw.line(canvas, YELLOW, (100, 100), (end_x, end_y), 3)

# ---- the window loop: hold the picture on screen until the window closes ----
running = 1
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = 0
    screen.blit(canvas, (0, 0))
    pygame.display.flip()
    clock.tick(60)

pygame.quit()

Predict: The line starts at (100, 100), faces heading 30, and is 200 long. Before you run: does the far end sit to the right or the left of the start, and above or below it? Then check the two printed numbers against your answer.

Heading 0 faces right and heading 90 faces down, so 30 is somewhere between those two.

What it actually prints (run without a screen, quit after 5 frames)

line runs from (100, 100) to (273.2, 200.0)

Right and below. Heading 30 is a third of the way from facing right to facing down, so the step is mostly across and partly down. The printed numbers agree: x went from 100 to 273.2, which is 173.2 across, and y went from 100 to 200.0, which is 100 down. Half of 200 is 100, so at heading 30 a step goes down by exactly half its length. The last value given to draw.line, the 3, is the thickness in pixels; leave it out and you get a line one pixel wide, with no error.

Chunk 4 of 8

A function that draws any polygon

polygon takes seven values, the most of any function in this class session. In order: the canvas to draw on, the colour, x and y for where to start, the heading to face first, how many sides, and how long each side is.

Think of a pen on the canvas. Each pass of the loop draws one side, moves the pen to the far end of that side, and turns by turn degrees. After the last side the function hands back where the pen is and which way it faces.

polygon(canvas, YELLOW, 320, 240, 0, 6, 80)
        canvas  colour  x    y  heading sides length

canvas, colour   what to draw on, and in what colour
x, y             where the pen starts
heading          which way the pen faces first
sides            how many sides the shape has
length           how long each side is
def polygon(canvas, color, x, y, heading, sides, length):
    turn = 360 / sides
    for i in range(sides):
        end_x, end_y = step_end(x, y, heading, length)
        pygame.draw.line(canvas, color, (x, y), (end_x, end_y), 3)
        x = end_x
        y = end_y
        heading = heading + turn
    return x, y, heading

x, y, heading = polygon(canvas, YELLOW, 320, 240, 0, 6, 80)
print(f"pen finished at ({round(x, 1)}, {round(y, 1)}) facing {round(heading, 1)}")

Add this code to the file you made in chunk 3. Where it goes matters. Functions are defined near the top of a program, after the imports and before any line that does work. The new function is separate from step_end: it starts with its own def at the left edge, not indented. Put it after the return line that ends step_end, leave one blank line between them, and keep it before pygame.init(). Put the lines that call the function under the comment # ---- your drawing, done once ----. That is after canvas.fill(BG), so the canvas exists before you draw on it, and before while running:, because the loop only shows what was drawn before it started. Then run the whole file.

Predict: The hexagon started at 320, 240 facing 0. Where does the pen finish, and which way is it facing?

Think about walking around a shape on the ground. When you have gone all the way round, where are you standing?

A hexagon has 6 sides, so the turn at each corner is 360 / 6 = 60, and the loop adds that turn to the heading six times. Add the six turns up.

What it actually prints (run without a screen)

pen finished at (320.0, 240.0) facing 360.0

Back at 320, 240, facing 360. The turns added to 360 and the sides were all the same length, so the pen walked a closed loop. Facing 360 is the same direction as facing 0, because one full turn brings you back to where you started. Session 8 shows a way to make Python say 0 instead of 360.

Chunk 6 of 8

Moving without drawing

To draw a second shape somewhere else, call polygon again with a different x and y. Nothing gets drawn between the two shapes, because a line appears only where you call draw.line. The three calls below start at three different points, so they make three separate shapes.

Chunk 7 of 8

A rosette: a loop around a loop

A loop inside a loop. The inner loop lives inside polygon and draws one shape. The outer loop calls polygon twelve times from the same point, each time with a starting heading 30 degrees further round. Twelve turns of 30 add up to 360, the same rule as the corners of one shape, so the copies go all the way round.

count = 0
for i in range(12):
    polygon(canvas, YELLOW, 320, 240, i * 30, 6, 60)
    count = count + 1
print(f"{count} hexagons drawn at headings 0 to {11 * 30}")
print(f"lines drawn in total: {count * 6}")

Predict: Twelve copies, thirty degrees apart. What heading does the last one start on?

range(12) gives i the values 0 up to 11, and the heading is i * 30. So the first copy starts at 0 times 30. What is i for the last copy?

What it actually prints (run without a screen)

330 degrees. Twelve thirties make 360, so a thirteenth copy would land back on the first one. Change 12 to 10 and leave the 30 alone, and the rosette has a gap in it, because ten thirties only add up to 300.

Chunk 8 of 8

Cycling colours with a remainder

Three colours and twelve shapes, so the colours have to repeat. % gives the remainder after dividing: 7 % 3 is 1, because 3 goes into 7 twice with 1 left over. Dividing by 3 can only leave a remainder of 0, 1, or 2, and those are exactly the three indexes the list has. So i % 3 turns any counter into an index that fits the list, and shape 3 comes back to colour 0. Session 8 spends a whole session on this operator.

RED = (220, 38, 38)
YELLOW = (252, 211, 77)
CREAM = (248, 250, 252)
colors = [RED, YELLOW, CREAM]
for i in range(12):
    print(f"shape {i} uses colour index {i % 3}, which is {colors[i % 3]}")

Predict: Twelve shapes, three colours. Which colour index does shape number 11 use?

Count the shapes on your fingers saying 0, 1, 2, 0, 1, 2 as you go. Or divide 11 by 3 and look at what is left over.

Use the loop counter i in the length: 20 + i * 10 gives 20, 30, 40, and so on up to 130. The counter is a value like any other, so it can be used in arithmetic, not just counted with.

If time runs out

Chunks 1, 2, 5, 7 and 8 all run as plain terminal programs with the drawing lines removed, printing coordinates instead. If pygame is not working on a machine, that is the fallback and it is a real session: the numbers are the lesson and the picture is the reward.

Running this in VS Code

Once, before the first run

Open the terminal in VS Code and install the library: pip install pygame. Check it worked with python -c "import pygame". It should print two lines of greeting from pygame and nothing else. A traceback here is an install problem, not a problem with your program. Those same two greeting lines appear at the top of the terminal every time you run a pygame program; the output boxes on this site leave them out.

Every run after that

The window often opens behind VS Code, so check the taskbar before deciding nothing happened. Close it with its own close button: these programs are written to end when the window closes, and stopping the terminal instead can leave the window stuck on screen. A window that will not close usually means the loop has no pygame.event.get() in it.

There is no turtle anywhere in this course. Turtle needs a library our VS Code setup does not have, so pygame does all the drawing, starting in session 5.
