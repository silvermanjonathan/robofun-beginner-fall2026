Chunk 1 of 8

The rule behind every closed shape

A full turn is 360 degrees. Walking a closed shape means you finish facing the way you started, so all your turns have to add to exactly 360. Divide 360 by the number of corners and you have the turn for each one.

for sides in range(3, 9):
    print(sides, "sides ->", 360 / sides, "degrees per turn")

Predict: A triangle has three corners. Is the turn at each corner 60 degrees or 120?

120. The inside angle of an equilateral triangle is 60, but the turn you make walking around the outside is 120. This trips up nearly everyone once, and it is the reason we compute the turn rather than remember it.

What actually happens

4 sides -> 90.0 degrees per turn
5 sides -> 72.0 degrees per turn
6 sides -> 60.0 degrees per turn
7 sides -> 51.42857142857143 degrees per turn
8 sides -> 45.0 degrees per turn

Chunk 2 of 8

Where a step lands

A pygame line needs both ends. You know where you are and which way you are facing, so the far end has to be worked out. cos gives how far across the step goes and sin gives how far down. Both want the angle in radians, so math.radians converts first. The function hands back two values at once, separated by a comma.

import math

def step_end(x, y, heading, length):
    end_x = x + length * math.cos(math.radians(heading))
    end_y = y + length * math.sin(math.radians(heading))
    return round(end_x, 1), round(end_y, 1)

print("heading 0  ", step_end(100, 100, 0, 50))
print("heading 90 ", step_end(100, 100, 90, 50))
print("heading 180", step_end(100, 100, 180, 50))
print("heading 45 ", step_end(100, 100, 45, 50))

Predict: A heading of 90 degrees. Does the step go up the screen or down it?

Down. The second coordinate grows downward in a window, so a positive turn goes clockwise and a heading of 90 points at the floor. Leave out math.radians and nothing crashes: math.cos(90) is a real number, about negative 0.45, and your shape comes out as a scribble. That is a silent bug with no error message.

What actually happens

heading 0   (150.0, 100.0)
heading 90  (100.0, 150.0)
heading 180 (50.0, 100.0)
heading 45  (135.4, 135.4)

Chunk 3 of 8

A window you can draw on

The drawing happens once, onto a canvas, above the loop. The loop below has one job: keep showing that canvas until you close the window. Copy the loop as it stands. Session 10 takes it apart line by line.

import math
import pygame

WIDTH = 640
HEIGHT = 480
BG = (27, 41, 81)
YELLOW = (252, 211, 77)

def step_end(x, y, heading, length):
    end_x = x + length * math.cos(math.radians(heading))
    end_y = y + length * math.sin(math.radians(heading))
    return end_x, end_y

pygame.init()
screen = pygame.display.set_mode((WIDTH, HEIGHT))
clock = pygame.time.Clock()
canvas = pygame.Surface((WIDTH, HEIGHT))
canvas.fill(BG)

# ---- your drawing, done once ----
end_x, end_y = step_end(100, 100, 30, 200)
print("line runs from (100, 100) to", (round(end_x, 1), round(end_y, 1)))
pygame.draw.line(canvas, YELLOW, (100, 100), (end_x, end_y), 3)

# ---- the harness: hold it on screen until the window closes ----
running = 1
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = 0
    screen.blit(canvas, (0, 0))
    pygame.display.flip()
    clock.tick(60)

pygame.quit()

Predict: The drawing line sits above the loop. What would happen if you moved canvas.fill(BG) down inside the loop?

The canvas would be wiped sixty times a second and the screen would stay empty. Drawing once and showing it many times is the whole shape of this program. The third argument to draw.line is the thickness; leave it out and you get a hairline, with no error.

What actually happens (run without a screen, quit after 5 frames)

line runs from (100, 100) to (273.2, 200.0)

Chunk 4 of 8

A function that draws any polygon

Seven parameters, which is the longest list of the term, and every one of them is a real choice: where to draw, which way to start, how many sides, how long each side. The loop draws one side, moves the pen to the far end, and adds the turn. It hands back where the pen finished.

def polygon(canvas, color, x, y, heading, sides, length):
    turn = 360 / sides
    for i in range(sides):
        end_x, end_y = step_end(x, y, heading, length)
        pygame.draw.line(canvas, color, (x, y), (end_x, end_y), 3)
        x = end_x
        y = end_y
        heading = heading + turn
    return x, y, heading

x, y, heading = polygon(canvas, YELLOW, 320, 240, 0, 6, 80)
print("pen finished at", (round(x, 1), round(y, 1)), "facing", round(heading, 1))

Predict: The hexagon started at 320, 240 facing 0. Where does the pen finish?

Back at 320, 240, facing 360. The turns added to 360 and the sides were all the same length, so the pen walked a closed loop. Facing 360 is the same direction as facing 0, which is the remainder idea from three weeks ahead arriving early.

Chunk 5 of 8

Proof that it closes, for any number of sides

Do not take the last claim on trust for one shape. Run the same function with three, six, and twelve sides and print where each one finishes.

for sides in [3, 6, 12]:
    x, y, heading = polygon(canvas, YELLOW, 320, 240, 0, sides, 60)
    print(sides, "sides finish at", (round(x, 1), round(y, 1)), "facing", round(heading, 1))

Predict: Three different shapes. How many different finishing positions?

One. All three come back to 320, 240 and all three finish facing 360. Change the length part way through and the shape stops closing, which is a good thing to break on purpose once.

Chunk 6 of 8

Moving without drawing

There is no pen to lift here. A line appears only where you call draw.line, so moving somewhere else is just choosing different numbers. That is simpler than it sounds and it is worth saying plainly.

RED = (220, 38, 38)
CREAM = (248, 250, 252)

polygon(canvas, YELLOW, 150, 120, 0, 5, 60)
polygon(canvas, RED, 470, 120, 0, 8, 40)
polygon(canvas, CREAM, 150, 360, 0, 3, 90)
print("three shapes drawn, no lines between them")

Predict: Three shapes in three corners. What would you add to draw a line from the first shape to the second?

One more pygame.draw.line call between the two starting points. In a turtle program you have to lift the pen to avoid that line. Here you have to ask for it.

Chunk 7 of 8

A rosette: a loop around a loop

The inner loop lives inside polygon and draws one shape. The outer loop draws the shape again from the same point with a different starting heading. Twelve copies, thirty degrees apart, use the same 360 rule at a larger scale.

count = 0
for i in range(12):
    polygon(canvas, YELLOW, 320, 240, i * 30, 6, 60)
    count = count + 1
print(count, "hexagons drawn at headings 0 to", 11 * 30)
print("lines drawn in total:", count * 6)

Predict: Twelve copies, thirty degrees apart. What heading does the last one start on?

330 degrees. Twelve thirties make 360, so a thirteenth copy would land back on the first one. Change 12 to 10 and leave the 30 alone and the rosette no longer closes, which looks like a bug and is really just arithmetic.

Chunk 8 of 8

Cycling colours with a remainder

Three colours and twelve shapes. The remainder operator wraps the counter around the list so shape 3 comes back to colour 0. This is a first look at an operator that gets a whole session of its own in three weeks.

colors = ["#DC2626", "#FCD34D", "#F8FAFC"]
for i in range(12):
    print(i, "uses colour slot", i % 3, colors[i % 3])

Predict: Twelve shapes, three colours. What slot does shape number 11 use?

Slot 2. Eleven divided by three leaves a remainder of two. Without the remainder you get an IndexError on the fourth shape.

If time runs out

Chunks 1, 2, 5, 7 and 8 all run as plain terminal programs with the drawing lines removed, printing coordinates instead. If pygame is not working on a machine, that is the fallback and it is a real session: the numbers are the lesson and the picture is the reward.

Running this in VS Code

Once, before the first run

Open the terminal in VS Code and install the library: pip install pygame. Check it worked with python -c "import pygame", which should print nothing at all. An error here is an install problem, not a problem with your program.

Every run after that

The window often opens behind VS Code, so check the taskbar before deciding nothing happened. Close it with its own close button: these programs are written to end when the window closes, and stopping the terminal instead can leave the window stuck on screen. A window that will not close usually means the loop has no pygame.event.get() in it.

There is no turtle anywhere in this course. Turtle needs a library our VS Code setup does not have, so pygame does all the drawing, starting in session 5.
