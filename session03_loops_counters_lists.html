Chunk 1 of 7

for and range repeat a block

range(5) hands out the numbers 0, 1, 2, 3, 4. Five numbers, starting at zero, stopping before five. The indented block runs once per number.

for step in range(5):
    print("step", step)

Predict: Five numbers. Does the list include 5?

No. It starts at 0 and stops before 5. Counting from zero is going to matter again in ten minutes when we index a list.

What actually happens

step 0
step 1
step 2
step 3
step 4

Chunk 2 of 7

The accumulator

A running total needs a name that exists before the loop starts, and a reassignment inside the loop. The name has to start at 0, outside the loop, or there is nothing to add to.

total = 0
for n in range(1, 6):
    total = total + n
print("total:", total)

Predict: range(1, 6) hands out which numbers, and what do they add up to?

1 through 5, and they add to 15. Two arguments to range means start here, stop before there.

What actually happens

total: 15

Chunk 3 of 7

A list holds many values under one name

Square brackets make a list. A number in brackets after the name pulls one value out. The first slot is 0, so the last slot of a three-item list is 2.

riders = ["Ada", "Grace", "Alan"]
print(riders[0])
print(riders[2])
print(len(riders))

Predict: len says 3. So what is the biggest number you can put in the brackets?

2. Three slots, numbered 0, 1, 2. The length and the last index are always one apart, which is the source of the next error you are about to write on purpose.

What actually happens

Ada
Alan
3

Chunk 4 of 7

IndexError, on purpose

Ask for a slot that does not exist. Read the error, and note that the number it names is the one you asked for.

riders = ["Ada", "Grace", "Alan"]
print(riders[3])

Predict: There are three riders. Does riders[3] give you Alan or an error?

An error. Alan is at slot 2. Off-by-one errors are so common that Python has a dedicated name for this one.

What actually happens

Traceback (most recent call last):
  File "session03.py", line 2, in <module>
    print(riders[3])
          ~~~~~~^^^
IndexError: list index out of range

Chunk 5 of 7

Counter with a gate, and best so far

Two patterns, one loop. The counter adds 1 only when the gate is True. Best so far keeps a name for the largest value seen and replaces it whenever something bigger turns up. Both names start before the loop.

heights = [52, 47, 61, 44, 58]
cleared = 0
tallest = 0
for h in heights:
    if h > 48:
        cleared = cleared + 1
    if h > tallest:
        tallest = h
print("cleared:", cleared)
print("tallest:", tallest)

Predict: Trace it on paper. What are the two numbers?

3 cleared and 61 tallest. Note that tallest changes three times on the way through: 52, then 61, and never again.

What actually happens

cleared: 3
tallest: 61

Chunk 6 of 7

The reveal: three built-in tools

Python already has these. You wrote them by hand first so you know what they do, which means you can now read a line that uses them without guessing.

heights = [52, 47, 61, 44, 58]
print(sum(heights))
print(max(heights))
print(min(heights))
print(len(heights))

Predict: Which of your two hand-written patterns does max replace?

Best so far. sum replaces the accumulator. Neither replaces the counter with a gate, because that one needs your condition. This is the shape of the whole library: it covers the common cases and leaves the specific ones to you.

What actually happens

262
61
44
5

Chunk 7 of 7

random.choice picks one for you

import random brings in code someone else wrote. random.choice picks one item from a list. random.seed makes the picking repeatable, which is how you test a program that is supposed to be unpredictable.

import random
random.seed(7)
riders = ["Ada", "Grace", "Alan"]
print(random.choice(riders))
print(random.choice(riders))

Predict: The seed is fixed. If you run this twice, do you get the same two names?

Yes, the same two every time, in the same order. Remove the seed line and you get a fresh pair on every run. Seeds are a testing tool, not a game feature.

What actually happens

Grace
Ada

Hinge question · reaches back two weeks

Before you build

Question: From session 1: a student writes total = 0 inside the loop instead of above it. The program runs, no error, wrong answer. What does it print for the heights list above, and why?

58, the last height. Resetting to 0 each pass throws away everything before it, so the final answer is just the last item added to zero. An error that does not crash is worse than one that does. This is the silent bug we spend all of session 7 on.
