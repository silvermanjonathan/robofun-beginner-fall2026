Opener · 10 minutes

Retrieval: gates

Paper first. Then check in the editor.

Question: Write a three-way gate on a variable called temp: above 90 prints hot, exactly 90 prints warm, anything else prints fine.

if temp > 90:
    print("hot")
elif temp == 90:
    print("warm")
else:
    print("fine")

Three tests, top to bottom, each with its own indented print. Python stops at the first True.

Question: Both sides are False. What does False and False evaluate to, and what does False or False evaluate to?

Both evaluate to False. and and or give different answers only when the two sides disagree: True and False is False, True or False is True.

Chunk 1 of 7

for and range repeat a block

range(5) hands out the numbers 0, 1, 2, 3, 4. Five numbers, starting at zero, stopping before five. The indented block runs once per number.

for step in range(5):
    print(f"step {step}")

Predict: Five numbers. Does the list include 5?

What it actually prints

step 0
step 1
step 2
step 3
step 4

No. It starts at 0 and stops before 5. Counting from zero is going to matter again in ten minutes when we index a list.

Chunk 2 of 7

The accumulator

A running total needs a name that exists before the loop starts, and a reassignment inside the loop. The name has to start at 0, outside the loop, or there is nothing to add to.

total = 0
for n in range(1, 6):
    total = total + n
print(f"total: {total}")

Predict: range(1, 6) hands out which numbers, and what do they add up to?

What it actually prints

total: 15

1 through 5, and they add to 15. Two arguments to range means start here, stop before there.

Chunk 3 of 7

A list holds many values under one name

A list is one value that holds many values in order. Square brackets make one, with commas between the values. Store it under a name the same way as any other value: riders = [...] makes riders a variable whose value is the whole list. Each value inside the list is called an item. To pull one item out, write the name and then a number in brackets. That number is the item's index: its position in the list, counting from 0, not from 1. So the first item has index 0, and the last item of a three-item list has index 2. The word slot is used on these pages to mean the same thing as index.

riders = ["Ada", "Grace", "Alan"]
print(riders[0])
print(riders[2])
print(len(riders))

Predict: len says 3. So what is the biggest number you can put in the brackets?

What it actually prints

Ada
Alan
3

2. Three slots, numbered 0, 1, 2. The length and the last index are always one apart, which is the source of the next error you are about to write on purpose.

Chunk 4 of 7

IndexError, on purpose

Ask for a slot that does not exist. Read the error, and note that the number it names is the one you asked for.

riders = ["Ada", "Grace", "Alan"]
print(riders[3])

Predict: There are three riders. Does riders[3] give you Alan or an error?

What it actually prints

Traceback (most recent call last):
  File "Jonathan_session03.py", line 2, in <module>
    print(riders[3])
          ~~~~~~^^^
IndexError: list index out of range

An error. Alan is at slot 2. Off-by-one errors are so common that Python has a dedicated name for this one.

Chunk 5 of 7

Counter with a gate, and best so far

Two patterns, one loop. The counter adds 1 only when the gate is True. Best so far keeps a name for the largest value seen and replaces it whenever something bigger turns up. Both names start before the loop.

heights = [52, 47, 61, 44, 58]
cleared = 0
tallest = 0
for h in heights:
    if h > 48:
        cleared = cleared + 1
    if h > tallest:
        tallest = h
print(f"cleared: {cleared}")
print(f"tallest: {tallest}")

Predict: Trace it on paper. What are the two numbers?

What it actually prints

cleared: 3
tallest: 61

3 cleared and 61 tallest. Note that tallest changes twice on the way through: to 52, then to 61, and never again.

Chunk 6 of 7

The reveal: three built-in tools

Python already has these. You wrote them by hand first so you know what they do, which means you can now read a line that uses them without guessing.

heights = [52, 47, 61, 44, 58]
print(sum(heights))
print(max(heights))
print(min(heights))
print(len(heights))

Predict: Which of your two hand-written patterns does max replace?

What it actually prints

262
61
44
5

Best so far. sum replaces the accumulator. Neither replaces the counter with a gate, because that one needs your condition. This is how the rest of Python's library works too: it covers the common cases and leaves the specific ones to you.

Chunk 7 of 7

random.choice picks one for you

import random brings in code someone else wrote. random.choice picks one item from a list. random.seed makes the picking repeatable, which is how you test a program that is supposed to be unpredictable.

import random
random.seed(7)
riders = ["Ada", "Grace", "Alan"]
print(random.choice(riders))
print(random.choice(riders))

Predict: The seed is fixed. If you run this twice, do you get the same two names?

What it actually prints

Grace
Ada

Yes, the same two every time, in the same order. Remove the seed line and you get a fresh pair on every run. Seeds are a testing tool, not a game feature.

Hinge question · from today's chunks

Before you build

heights = [52, 47, 61, 44, 58]
for h in heights:
    total = 0
    total = total + h
print(f"total: {total}")

Question: From chunk 2 today: this student wrote total = 0 inside the loop instead of above it. The program runs, no error, wrong answer. What does it print for the heights list, and why?

What it actually prints

total: 58
heights = [52, 47, 61, 44, 58]
total = 0
for h in heights:
    total = total + h
print(f"total: {total}")

58, the last height. Resetting to 0 each pass throws away everything before it, so the final answer is just the last item added to zero. An error that does not crash is worse than one that does. This is the silent bug we spend all of session 7 on.
