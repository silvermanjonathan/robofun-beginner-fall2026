A Mondrian made of rectangles

One function that draws a tile, called again and again with your own numbers

Monday section Mon Nov 2Friday section Fri Oct 23Length 90 minutesNew 8 items

What is new today

a window, a colour as three numbers, pygame.draw.rect, x, y, width, height, a border with a thickness, a function that draws, tiles that touch, a picture made by calling one function many times.

Deliberately re-used: Session 5: def, a parameter, an argument, and a function called more than once.

Piet Mondrian was a Dutch painter who, about a hundred years ago, made paintings out of nothing but rectangles: red, blue, yellow, and white, with thick black lines between them. Today the class makes one in a window. The function that draws one tile is three lines long and the students write it one line at a time, with the hints opening one inside the next. After that they copy the calls and change the numbers. Every number a student changes moves something they can see, which is the point of the session. The window code at the top and bottom of the file is copied, not taught; session 11 takes it apart. Nobody needs to understand the loop today.

Opener · 10 minutes

Retrieval: a function with parameters

Paper first. Then open the editor, make Jonathan_session06.py with your own first name in place of Jonathan, and check the first answer.

Question: Write a function called greet with one parameter, name, that prints Welcome and the name. Then call it twice with two different names.

def greet(name):
    print(f"Welcome, {name}.")

greet("Ada")
greet("Grace")

The def line, the print indented under it, then two calls at the left edge. name is the parameter, written once on the def line. "Ada" and "Grace" are the arguments, one per call. Today's function has five parameters, and it gets called six times.

Question: In def area(w, h): and the call area(3, 4), which words are parameters, which values are arguments, and what is h while that call runs?

w and h are the parameters. 3 and 4 are the arguments. The arguments fill the parameters in order, so w is 3 and h is 4 for that one call. Order is the whole thing: area(4, 3) gives the same number, but today tile(RED, 40, 40, 200, 120) and tile(RED, 40, 40, 120, 200) draw two different shapes.

Chunk 1 of 6

A white window

Every program this term has put its words in the terminal. This one opens a window instead, and the words stay in the terminal. Type it all. The lines at the top set the window up and the lines at the bottom keep it open until you close it; both are copied, not studied. Session 11 takes the loop apart. Today the only part that matters is the empty space under the comment in the middle. That is where the drawing goes.

Every colour is three numbers in parentheses: how much red, how much green, and how much blue, each from 0 to 255. All three at 255 is white and all three at 0 is black. canvas is a blank picture the size of the window, kept in memory, and canvas.fill(WHITE) paints all of it white. The loop at the bottom copies the canvas onto the window sixty times a second.

import pygame

WIDTH = 640
HEIGHT = 480
WHITE = (255, 255, 255)
BLACK = (0, 0, 0)
RED = (220, 38, 38)
BLUE = (37, 99, 235)
YELLOW = (252, 211, 77)

pygame.init()
screen = pygame.display.set_mode((WIDTH, HEIGHT))
clock = pygame.time.Clock()
canvas = pygame.Surface((WIDTH, HEIGHT))
canvas.fill(WHITE)

# ---- your drawing, done once ----

# ---- the window loop: hold the picture on screen until the window closes ----
running = 1
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = 0
    screen.blit(canvas, (0, 0))
    pygame.display.flip()
    clock.tick(60)

pygame.quit()

Predict: The program has no print in it. When you run it, what shows up in the terminal, and what shows up on the screen?

Nothing printed in the terminal. This was run without a screen and quit after 5 frames, and it printed nothing because the window is the output. Words go in the terminal, visuals go in the window.

The terminal shows only pygame's two greeting lines, and a white window opens. It can open behind VS Code, so check the taskbar before deciding nothing happened. Close it with its own close button. Words go in the terminal and visuals go in the window, and that split holds all term.

Chunk 2 of 6

One rectangle

pygame.draw.rect draws a rectangle on the canvas. It takes the canvas, the colour, and then four numbers in parentheses: x, how far across the rectangle starts; y, how far down it starts; w, how wide it is; and h, how tall it is. The top left corner of the window is 0, 0, and y counts down from the top, not up from the bottom. That is the one way a window is unlike graph paper.

The print is a probe. It works out where the right edge lands, so you can check it against what you see.

pygame.draw.rect(canvas, RED, (40, 40, 200, 120))
print(f"the red tile runs from x = 40 to x = {40 + 200}")

Add these lines to the file you made in chunk 1, under the comment # ---- your drawing, done once ----. That is after canvas.fill(WHITE), so the canvas exists before you draw on it, and before while running:, because the loop only shows what was drawn before it started. Then run the whole file.

Predict: The tile starts 40 across and is 200 wide. Where is its right edge? And if you changed the 40 for y to 300, would the tile move down the window or up it?

The right edge is where the tile starts plus how wide it is.

Larger y numbers are lower on the screen, because y counts down from the top.

What it actually prints (run without a screen)

the red tile runs from x = 40 to x = 240

At 240, because 40 plus 200 is 240, and the probe prints the same number. A y of 300 moves the tile down, to a strip that starts 300 from the top and ends at 420. The width and height do not say where the tile ends; they say how big it is. To know where it ends, add.

Chunk 3 of 6

A black border

A Mondrian has thick black lines between the colours. pygame.draw.rect draws a border instead of a filled shape when you give it a fifth value: the thickness of the line, in pixels. Leave it out and the rectangle is filled.

Draw the red fill first and the black border second, with the same four numbers. Later drawing goes on top of earlier drawing, the way a later coat of paint covers an earlier one.

pygame.draw.rect(canvas, RED, (40, 40, 200, 120))
pygame.draw.rect(canvas, BLACK, (40, 40, 200, 120), 10)
print("one red tile with a black border")

Add these lines to the file you made in chunk 1, under the comment # ---- your drawing, done once ----. That is after canvas.fill(WHITE), so the canvas exists before you draw on it, and before while running:, because the loop only shows what was drawn before it started. Then run the whole file.

Predict: The same four numbers appear on both lines. What does the 10 on the second line do? And if you swapped the two lines, what would you see?

Try it. Change the 10 to 30, run it, then take it out altogether and run it again.

What it actually prints (run without a screen)

one red tile with a black border

The 10 is the thickness of the border, so the black line is ten pixels wide. Take it out and the black rectangle is filled, so it covers the red one completely. Swap the two lines and the red fill is drawn on top of the border and covers it, so the border disappears except where it sticks out. Fill first, border second.

Chunk 4 of 6

A function that draws one tile

Every tile needs those same two lines with the same four numbers twice. Six tiles would be twelve lines, and a change to one number would have to be made twice. So the two lines go in a function. Session 5's greet had one parameter. This one has five: the colour and the four numbers. Each line is a question for the room before it goes on the screen.

pygame.draw.rect(canvas, RED, (40, 40, 200, 120))
pygame.draw.rect(canvas, BLACK, (40, 40, 200, 120), 10)

Line 1. What goes next? The function is called tile. It needs to be told a colour and the four numbers. Which line starts it?

A function starts with def, its name, parentheses, and a colon. The blanks the caller fills in go inside the parentheses, with commas between them.

Five blanks: the colour first, then x, y, w, h in the same order as chunk 2.

Fill the blank.

def tile(____, x, y, w, h):
def tile(color, x, y, w, h):

Line 2. What goes next? What is the first thing the function draws, and how far in is the line indented?

Chunk 3's first line, the filled rectangle, indented four spaces so it belongs to the def.

In chunk 3 the colour was RED and the numbers were written in. Here they come from the parameters, so the line uses the parameter names instead.

Fill the blank.

    pygame.draw.rect(canvas, color, (____, y, w, h))
    pygame.draw.rect(canvas, color, (x, y, w, h))

Line 3. What goes next? What does the function draw second?

Chunk 3's second line, the border. The border is always black, so BLACK stays as it is. The four numbers come from the parameters.

Fill the blank.

    pygame.draw.rect(canvas, BLACK, (x, y, w, h), ____)
    pygame.draw.rect(canvas, BLACK, (x, y, w, h), 10)

Line 5. What goes next? The function is written and draws nothing yet. Which line draws the red tile from chunk 3 with it?

A call: the name, then parentheses with five arguments in the order of the parameters.

The first argument is the colour. The other four are chunk 3's numbers.

Fill the blank.

tile(RED, 40, 40, ____, 120)
tile(RED, 40, 40, 200, 120)

At the left edge, under the drawing comment, with an empty line between the function and the call.

Line 6. What goes next? A blue tile, the same height, right next to the red one with no gap. Where does it start?

It starts where the red tile ends. Chunk 2 worked out where that is.

The red tile runs from 40 to 240, so the blue one starts at x = 240. Same y, same height, any width you like.

Fill the blank.

tile(BLUE, ____, 40, 160, 120)
tile(BLUE, 240, 40, 160, 120)
def tile(color, x, y, w, h):
    pygame.draw.rect(canvas, color, (x, y, w, h))
    pygame.draw.rect(canvas, BLACK, (x, y, w, h), 10)

tile(RED, 40, 40, 200, 120)
tile(BLUE, 240, 40, 160, 120)
print(f"the blue tile starts at x = {40 + 200}, where the red one ends")

Two places in the file you made in chunk 1. The three lines of the function go near the top, after the colour lines and before pygame.init(), with an empty line on each side. The function uses canvas, which is made further down, and that is fine: a def does not run anything. The function only runs when it is called, and by then the canvas exists. The calls go under the comment # ---- your drawing, done once ----, in place of chunk 3's two lines. Then run the whole file.

Predict: Two calls to tile. How many rectangles get drawn, and why is the black line between the red and the blue thicker than the line round the outside?

What it actually prints (run without a screen)

the blue tile starts at x = 240, where the red one ends

Four: each call draws a fill and then a border, so two calls draw two fills and two borders. A border is drawn inside its own tile. The red tile's right border ends at x = 240 and the blue tile's left border starts there, so the two borders sit side by side and join into one line twice as thick, 20 pixels instead of 10. Every line between two tiles in a Mondrian comes out that way, and the outside edge of the picture stays thin. That is why tiles that touch share a number.

Chunk 5 of 6

A whole Mondrian

Six tiles that fill the window exactly. The plan is on the figure: the window is 640 across and 480 down, and the tiles are cut by one line across at 300 and one line down at 400, with the bottom right cut again at 400. Each tile is one call to tile. Read the plan before you type: every number in the calls is on it.

Tiles that touch share a number. The red tile is 400 wide and starts at 0, so the white tile beside it starts at x = 400. The top row is 300 tall, so every tile in the bottom row starts at y = 300. The probe prints the right edge of each tile in the top row, which should be 400 and 640.

What goes next? The red tile is tile(RED, 0, 0, 400, 300). The white tile beside it fills the rest of the top row. What are its four numbers?

It starts where the red tile ends, at the top of the window.

x is 0 plus 400. y is 0. It is as tall as the red tile. The window is 640 across, so its width is 640 take away 400.

Fill the blanks.

tile(WHITE, ____, 0, ____, 300)
tile(RED, 0, 0, 400, 300)
tile(WHITE, 400, 0, 240, 300)
tile(BLUE, 0, 300, 160, 180)
tile(WHITE, 160, 300, 240, 180)
tile(YELLOW, 400, 300, 240, 100)
tile(WHITE, 400, 400, 240, 80)
print(f"top row right edges: {0 + 400} and {400 + 240}")
print(f"bottom row bottom edges: {300 + 180} and {400 + 80}")

Replace the two calls under the drawing comment with these six. The function stays where it is.

tile(WHITE, 400, 0, 240, 300). The other four calls follow the plan the same way: find where the tile starts, then how far it goes to the next line or the edge of the window.

Predict: Three tiles are white on a white canvas. Why can you still see them?

What it actually prints (run without a screen)

top row right edges: 400 and 640
bottom row bottom edges: 480 and 480

Because of the borders. The white fill is the same colour as the canvas, so it changes nothing you can see, but every tile also draws its black border, and that is what makes the white tiles look like tiles. The probe prints 400 and 640 for the top row and 480 and 480 for the bottom, which means every tile reaches the next tile or the edge of the window with no gap.

Chunk 6 of 6

Make it yours: one number per run

Now change things. One number per run, and before each run say what will move. The three kinds of change: swap a colour name for another, move a tile by changing its x or y, or resize it by changing its w or h. A resize changes where the tile ends, so the tile next to it has to change too, or a gap opens.

Here the red tile has been made 300 wide instead of 400, and nothing else was changed.

tile(RED, 0, 0, 300, 300)
tile(WHITE, 400, 0, 240, 300)
tile(BLUE, 0, 300, 160, 180)
tile(WHITE, 160, 300, 240, 180)
tile(YELLOW, 400, 300, 240, 100)
tile(WHITE, 400, 400, 240, 80)
print(f"the red tile now ends at x = {0 + 300}, and the white one still starts at 400")

Change one number in the calls you already have. Run. Say what moved. Then change the next number.

Predict: The red tile now ends at 300 and the white tile beside it still starts at 400. What is between 300 and 400 in the top row?

Nothing was drawn there. What colour is the canvas underneath, and does it have a border?

What it actually prints (run without a screen)

the red tile now ends at x = 300, and the white one still starts at 400

A white strip 100 wide with no black border on its left or right, so it does not look like a tile. It looks like a hole. To close it, the white tile has to start at 300 and be 340 wide, so that it ends at 640 again. Changing one tile's width changes where it ends, and its neighbour's x has to follow. That is the build.

Hinge question · reaches back to session 5

Before you build

Question: From session 5: in tile(RED, 40, 40, 200, 120), which word in the function is a parameter and which value in the call is an argument? What is w while this call runs, and what is it in the call right after, tile(BLUE, 240, 40, 160, 120)?

color, x, y, w, and h are the parameters: the blanks on the def line. RED, 40, 40, 200, and 120 are the arguments: the values in the call. The arguments fill the parameters in order, so w is 200 during the first call and 160 during the second. The function does not remember anything between calls; each call fills all five blanks again.

Build · 15 minutes

Build: your own Mondrian

You are making a picture of your own, and the plan comes first, on paper. Draw a rectangle for the window and write 640 along the top and 480 down the side. Cut it into tiles with straight lines: at least six tiles, and every line goes all the way to another line or to the edge. Then write the four numbers for each tile next to it. Tiles that touch share a number, so write the shared numbers once and copy them.

  1. Plan it on paper: a 640 by 480 rectangle cut into at least six tiles. Write x, y, w, and h for every tile.
  2. Start from your chunk 5 file. Keep the setup, the function, and the loop exactly as they are, and delete the six calls.
  3. Write one call to tile per tile on your plan, one at a time. Run after each call and check that the tile landed where the plan says.
  4. Check the edges: for every pair of tiles that touch, the number where one ends is the number where the other starts. A gap with no border is a tile you have not drawn yet.
  5. Add a colour of your own. Pick three numbers from 0 to 255, give them a capitalised name next to the other colours, and use it in one call.

Running this in VS Code

Once, before the first run

Open the terminal in VS Code and install the library: pip install pygame. Check it worked with python -c "import pygame". It should print two lines of greeting from pygame and nothing else. A traceback here is an install problem, not a problem with your program. Those same two greeting lines appear at the top of the terminal every time you run a pygame program; the output boxes on this site leave them out.

Every run after that

The window often opens behind VS Code, so check the taskbar before deciding nothing happened. Close it with its own close button: these programs are written to end when the window closes, and stopping the terminal instead can leave the window stuck on screen. A window that will not close usually means the loop has no pygame.event.get() in it.

There is no turtle anywhere in this course. Turtle needs a library our VS Code setup does not have, so pygame does all the drawing, starting in session 6.
