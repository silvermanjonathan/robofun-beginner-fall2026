Chunk 1 of 6

A comparison is a question with a yes or no answer

Comparing two values hands back True or False. Those are values like any other. You can print them. Every comparison sign is typed as ordinary keys: == is two equals signs, != is an exclamation mark then an equals sign, and <= and >= are two keys each. There is no single slashed-equals character in Python.

height = 52
print(height > 48)
print(height == 48)
print(height != 48)

Predict: Three comparisons on the same number. How many print True?

What it actually prints

True
False
True

Two. 52 is greater than 48, so the first is True. It is not equal to 48, so the second is False and the third is True. Count them before you run, every time.

Chunk 2 of 6

The three-way gate

The part after if is called the condition. A condition is a comparison, or anything else that comes out True or False. if runs its block when its condition is True. elif gets checked only when everything above it was False. else catches whatever is left. Python checks top to bottom and stops at the first True.

What a gate is

A gate is an if line together with the indented lines under it. It has two parts. The condition is the test after the word if. It comes out True or False. The block is the indented lines under it. They run only when the condition is True, and are skipped when it is False. The condition decides whether the block runs.

if height > 48:                ← condition
    print("Cleared to ride.")  ← block
elif height == 48:             ← next condition
    print("Borderline. Ask staff.")  ← its block
else:                            ← everything else
    print("Not tall enough yet.")  ← its block
condition: a True or False test block: indented lines that run only when their condition is True

The three tests together are one gate with three ways through. Python reads it top to bottom, takes the first way whose condition is True, and skips the rest. One block runs, never two. else has no condition; it is the way through when every test above it was False. Think of the height gate at the coaster: one test, and you either go through or you do not.

height = 48
if height > 48:
    print("Cleared to ride.")
elif height == 48:
    print("Borderline. Ask staff.")
else:
    print("Not tall enough yet.")

Predict: Height is exactly 48. Which of the three lines prints?

What it actually prints

Borderline. Ask staff.

The middle one. The first test is False because 48 is not greater than 48, so Python moves down to the elif. Boundary values are where gate bugs live.

Chunk 3 of 6

One equals sign is an order, two is a question

This is the single most common typo in the room. Run it and read the error.

height = 52
if height = 48:
    print("Borderline.")

Predict: Does this print nothing, or does it crash?

What it actually prints

  File "Jonathan_session02.py", line 2
    if height = 48:
       ^^^^^^^^^^^
SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?

It crashes before it runs a single line, and Python tells you what it wanted instead. One equals sign stores a value. Two equals signs ask a question.

Chunk 4 of 6

and: both must be True

Real gates check more than one thing. and hands back True only when both sides are True. Nothing is nested here; the two conditions sit side by side on one line.

height = 52
has_ticket = True
if height > 48 and has_ticket:
    print("Board the coaster.")
else:
    print("Step aside.")

Predict: Set has_ticket to False on paper. Which line prints then?

What it actually prints

Board the coaster.

Step aside. With and, one False sinks the whole condition. Change the value and rerun to confirm, one change per run.

Chunk 5 of 6

or: one is enough

or hands back True when either side is True. Read it out loud with the word or in it and it behaves the way English does.

is_staff = False
has_pass = True
if is_staff or has_pass:
    print("Gate opens.")
else:
    print("Gate stays shut.")

Predict: Both names are on the screen. Does the gate open?

What it actually prints

Gate opens.

Yes. has_pass is True, and with or that is enough on its own.

Chunk 6 of 6

A while loop and its stopping condition

A while loop has a condition too, the same kind of True or False test as an if. It repeats its block as long as the condition is True and stops the first time it is False. That makes it a stopping condition: read it and you know what will make the loop stop. Every while loop you write this semester has a stopping condition you can point at. This one stops when the answer is yes or no and nothing else.

answer = ""
while answer != "yes" and answer != "no":
    answer = input("Ready? Type yes or no: ")
print("Recorded:", answer)

Predict: Someone types maybe, then soon, then yes. How many times does the question appear?

What it actually prints

Ready? Type yes or no: maybe
Ready? Type yes or no: soon
Ready? Type yes or no: yes
Recorded: yes

Three times. The condition is checked before each pass. Once the answer is yes, the stopping condition is no longer True, so the loop stops and the print runs.

height = input("Height in inches: ")

Question: From session 1: a rider types 52 at an input prompt and the program crashes on the line that says if height > 48:. The gate is written correctly. What is wrong?

height = input("Height in inches: ")
height = int(height)
if height > 48:
    print("Cleared to ride.")
else:
    print("Not tall enough yet.")

height is still text, and Python will not compare text with a number. The last line of the error says TypeError. The missing line is height = int(height), before the gate. Session 1's trap, wearing a session 2 costume.
