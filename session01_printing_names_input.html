First session. Nothing to retrieve yet, so the ten minutes go to machine setup and one shared rule: read it, trace it, then run it.

Opener · 10 minutes

Setup and the house rule

Open the editor and make a file called Jonathan_session01.py, with your own first name in place of Jonathan. Every file you make this term starts with your first name, then an underscore, then the session. Write your name in a comment on line 1 as well. Then, before anyone runs anything, the rule for the whole semester: you say out loud what a line will do before you press run. Being wrong out loud is the point. It is how you find out what you actually believe.

Chunk 1 of 8

One line, one job

A program is a list of instructions. Python does them top to bottom, one at a time, and then stops. print puts words on the terminal.

print("Robofun terminal is live.")

Predict: The quote marks are in the code. Will they be in the output?

What it actually prints

Robofun terminal is live.

No. The quotes tell Python where the text starts and stops. They are punctuation for Python, not part of your message.

Chunk 2 of 8

The misfire, on purpose

Now break it. Type pritn instead of print and run it. You are going to read errors all semester, so you may as well meet one you built yourself.

pritn("Robofun terminal is live.")

Predict: Python is going to complain. Which word will it complain about?

What it actually prints

Traceback (most recent call last):
  File "Jonathan_session01.py", line 1, in <module>
    pritn("Robofun terminal is live.")
    ^^^^^
NameError: name 'pritn' is not defined. Did you mean: 'print'?

It names pritn, not the message. Python does not know that word. Read the last line of an error first. It tells you the category and the word involved.

Chunk 3 of 8

A name for a value

The equals sign does not mean equals here. It means put this value under this name. After that line, the name works anywhere you would have written the value. A name that holds a value is called a variable. That is the word every Python book uses, so this course uses it too: player is a variable, and its value right now is Ada.

player = "Ada"
print(player)
print("player")

Predict: Two print lines, one with quotes and one without. Do they print the same thing?

What it actually prints

Ada
player

No. Without quotes, Python looks up the name and finds Ada. With quotes, it just prints the six letters you typed. This is the most common first-week mix-up in the room.

Chunk 4 of 8

Reassignment reads right to left

A name can be pointed at a new value. When the old name appears on both sides, work out the right side first, then store the answer back under the name.

score = 10
print(score)
score = score + 5
print(score)

Predict: Line 3 has score on both sides. What does the second print show?

What it actually prints

10
15

15. Python computes 10 + 5 first, then stores 15 under score. The old 10 is gone.

Chunk 5 of 8

input always hands back text

input stops the program, waits for typing, and hands back what was typed. It hands back text, always, even when the person typed digits. Run this with 3 as the answer.

age = input("Robot age in years: ")
print(age + 1)

Predict: You typed the number 3. Does age + 1 give you 4?

What it actually prints

Robot age in years: 3
Traceback (most recent call last):
  File "Jonathan_session01.py", line 2, in <module>
    print(age + 1)
          ~~~~^~~
TypeError: can only concatenate str (not "int") to str

No. You get a TypeError. The 3 you typed is the text "3", and Python will not add 1 to text. Text plus text is allowed; text plus number is not.

Chunk 6 of 8

Two kinds of value, and type() tells them apart

Python keeps text and whole numbers as two different kinds of value, and it calls the kind a type. type() tells you which kind you have. str is short for string, which is Python's word for text. int is short for integer, a whole number. Quote marks make text, even around digits. Run this with 3 as the answer again.

print(type("4"))
print(type(4))
age = input("Robot age in years: ")
print(type(age))

Predict: Three type() calls. Which of them say str, and which say int?

What it actually prints

<class 'str'>
<class 'int'>
Robot age in years: 3
<class 'str'>

The first is str, because the quotes make it text. The second is int. The third is str as well: you typed 3, but input handed it back as text, which is why chunk 5 crashed. Text and number are different types, and a plus sign will not mix them. The word class in the output is Python's way of saying kind: read <class 'str'> as text and <class 'int'> as whole number.

Chunk 7 of 8

int() changes the type, on one line of its own

int() takes text that looks like a whole number and hands back the same value as a number. It changes the type from str to int. Do the type change on its own line while you are learning. You will see it folded into one line in other people's code later.

age = input("Robot age in years: ")
age = int(age)
print(age + 1)

Predict: Same program with one line added. What changes?

What it actually prints

Robot age in years: 3
4

Now age holds the number 3 rather than the text 3, so adding 1 works. Add print(type(age)) after line 2 and it says int. This trap comes back every time a program asks for a number, so it goes on your ledger card today.

Chunk 8 of 8

f-strings put values inside a sentence

Putting an f in front of the opening quote lets you drop a name into the middle of a sentence using curly braces. It is shorter than gluing pieces together with plus signs, and it does not care whether the value is text or a number.

player = "Ada"
score = 15
print(f"{player} has {score} points.")

Predict: What lands in the braces, the name or the value?

What it actually prints

Ada has 15 points.

The value. Python looks up each name inside the braces and drops the value in. Forget the f and you print the braces themselves, which is a good bug to see once.

Hinge question · from today's chunks

Before you build

Question: Someone writes total = input("How many tickets? ") and then print(total + 2). The program crashes. Name the fix in one line of code.

total = input("How many tickets? ")
total = int(total)
print(total + 2)

total = int(total) before the print. Or convert inside the print with int(total) + 2. Either answer is correct; the first is the one we write this term.

Build · 25 minutes

Build: the rider card

Picture the gate at a theme park roller coaster. Before anyone gets on, the person at the gate asks three things: your name, how tall you are, and how many tickets you have. Then they say it back to you, so you can check it. Your program is that person at the gate. It asks the three questions in the terminal, and the person typing the answers is the rider. The height and the tickets are numbers, and that is where the trap from chunks 5 to 7 comes back.

  1. Ask for a rider name and store it.
  2. Ask for a height in inches. It comes back as text, so change its type to a number with int(), on its own line.
  3. Ask for a number of tickets, and change its type the same way.
  4. Print one f-string sentence that uses all three values.
  5. Add 1 to the ticket count and print a second sentence showing the new total.

Expected and got

Fill in the left column before you run. Fill in the right column after.

ExpectedGot
Line 4 prints all three values in one sentence
Line 6 shows the ticket count one higher than typed
No quote marks appear in the output
