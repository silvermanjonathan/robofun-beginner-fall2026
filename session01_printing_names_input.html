Opener · 10 minutes

Setup and the house rule

Open the editor, make a file called session01.py, and write your name in a comment on line 1. Then, before anyone runs anything, the rule for the whole semester: you say out loud what a line will do before you press run. Being wrong out loud is the point. It is how you find out what you actually believe.

Chunk 1 of 7

One line, one job

A program is a list of instructions. Python does them top to bottom, one at a time, and then stops. print puts words on the terminal.

print("Robofun terminal is live.")

Predict: The quote marks are in the code. Will they be in the output?

No. The quotes tell Python where the text starts and stops. They are punctuation for Python, not part of your message.

What actually happens

Robofun terminal is live.

Chunk 2 of 7

The misfire, on purpose

Now break it. Type pritn instead of print and run it. You are going to read errors all semester, so you may as well meet one you built yourself.

pritn("Robofun terminal is live.")

Predict: Python is going to complain. Which word will it complain about?

It names pritn, not the message. Python does not know that word. Read the last line of an error first. It tells you the category and the word involved.

What actually happens

Traceback (most recent call last):
  File "session01.py", line 1, in <module>
    pritn("Robofun terminal is live.")
    ^^^^^
NameError: name 'pritn' is not defined. Did you mean: 'print'?

Chunk 3 of 7

A name for a value

The equals sign does not mean equals here. It means put this value under this name. After that line, the name works anywhere you would have written the value.

player = "Ada"
print(player)
print("player")

Predict: Two print lines, one with quotes and one without. Do they print the same thing?

No. Without quotes, Python looks up the name and finds Ada. With quotes, it just prints the six letters you typed. This is the most common first-week mix-up in the room.

What actually happens

Ada
player

Chunk 4 of 7

Reassignment reads right to left

A name can be pointed at a new value. When the old name appears on both sides, work out the right side first, then store the answer back under the name.

score = 10
print(score)
score = score + 5
print(score)

Predict: Line 3 has score on both sides. What does the second print show?

15. Python computes 10 + 5 first, then stores 15 under score. The old 10 is gone.

What actually happens

10
15

Chunk 5 of 7

input always hands back text

input stops the program, waits for typing, and hands back what was typed. It hands back text, always, even when the person typed digits. Run this with 3 as the answer.

age = input("Robot age in years: ")
print(age + 1)

Predict: You typed the number 3. Does age + 1 give you 4?

No. You get a TypeError. The 3 you typed is the text "3", and Python will not add 1 to text. Text plus text is allowed; text plus number is not.

What actually happens

Robot age in years:
Traceback (most recent call last):
  File "session01.py", line 2, in <module>
    print(age + 1)
          ~~~~^~~
TypeError: can only concatenate str (not "int") to str

Chunk 6 of 7

int() converts, on one line of its own

int() takes text that looks like a whole number and hands back the number. Do the conversion on its own line while you are learning. You will see it folded into one line in other people's code later.

age = input("Robot age in years: ")
age = int(age)
print(age + 1)

Predict: Same program with one line added. What changes?

Now age holds the number 3 rather than the text 3, so adding 1 works. This trap comes back every time a program asks for a number, so it goes on your ledger card today.

What actually happens

Robot age in years: 4

Chunk 7 of 7

f-strings put values inside a sentence

Putting an f in front of the opening quote lets you drop a name into the middle of a sentence using curly braces. It is shorter than gluing pieces together with plus signs, and it does not care whether the value is text or a number.

player = "Ada"
score = 15
print(f"{player} has {score} points.")

Predict: What lands in the braces, the name or the value?

The value. Python looks up each name inside the braces and drops the value in. Forget the f and you print the braces themselves, which is a good bug to see once.

What actually happens

Ada has 15 points.

Hinge question · reaches back two weeks

Before you build

Question: Someone writes total = input("How many tickets? ") and then print(total + 2). The program crashes. Name the fix in one line of code.

total = int(total) before the print. Or convert inside the print with int(total) + 2. Either answer is correct; the first is the one we write this term.
