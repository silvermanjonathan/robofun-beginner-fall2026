Retrieval: a list slot, and the counter

Paper first.

Question: In tic tac toe, board is a list of nine strings, "1" to "9". Write the line that puts X in the middle square. Then say what "5" in board gives after that line has run.

board[4] = "X"

The middle square is square 5, and its index is one less, so the line changes slot 4. After it has run, "5" in board gives False, because no item in the list is "5" any more. That is how the game knew a square was taken.

Question: Write the loop that counts how many items in nums are over 100.

A counter with a gate, from session 3. The counter starts at 0 above the loop, and the gate inside the loop decides whether this pass adds 1.

Chunk 1 of 8

Two lists that have to stay lined up

This is the obvious way to store paired information, and it is the way most people try first. It works right up until the two lists stop matching, and then it keeps working while being wrong.

names = ["Ada", "Grace", "Alan"]
scores = [15, 22, 9]
print(names[1], "has", scores[1], "points")

names = ["Ada", "Zoe", "Grace", "Alan"]
print(names[1], "has", scores[1], "points")

Predict: A new rider is added to the names list only. What does the second print say?

What it actually prints

Grace has 22 points
Zoe has 22 points

That Zoe has 22 points, which belong to Grace. No error, no warning. In a game with five parallel lists for position, speed, size and colour, one insert breaks everything and nothing tells you.

Chunk 2 of 8

A dictionary pairs a key with a value

Curly braces, and a colon between each key and its value. Look a value up by writing the key in square brackets. There are no slot numbers here and no order to keep in step.

scores = {"Ada": 15, "Grace": 22, "Alan": 9}
print(scores["Grace"])
print(len(scores))

Predict: You look up Grace by name rather than by number. What happens to the pairing problem from chunk 1?

What it actually prints

22
3

It is gone. The name and the score are stored together, so there is no second list to keep lined up. Each key holds exactly one value, which is the same rule as a function from session 5: one input, one output.

Chunk 3 of 8

Add, change, and ask for something that is not there

Assigning to a key that exists changes it. Assigning to a key that does not exist creates it. Looking up a key that does not exist is an error with its own name.

scores = {"Ada": 15, "Grace": 22}
scores["Ada"] = 16
scores["Katherine"] = 30
print(scores)
print(scores["Nobody"])

Predict: Same line shape for changing Ada and for adding Katherine. How does Python know which one you meant?

What it actually prints

{'Ada': 16, 'Grace': 22, 'Katherine': 30}
Traceback (most recent call last):
  File "Jonathan_session10.py", line 5, in <module>
    print(scores["Nobody"])
          ~~~~~~^^^^^^^^^^
KeyError: 'Nobody'

It does not need to know. If the key is there it is replaced, and if it is not it is created. The last line is a KeyError, which is number six on your error list.

Chunk 4 of 8

in checks the keys, and gates against KeyError

in on a dictionary asks about keys, not values. This is the gate that stops the error from the last chunk.

scores = {"Ada": 16, "Grace": 22}
print("Ada" in scores)
print("Nobody" in scores)
print(16 in scores)

who = "Nobody"
if who in scores:
    print(who, "scored", scores[who])
else:
    print(who, "is not on the list")

Predict: Ada's score is 16. Does 16 in scores give True?

What it actually prints

True
False
False
Nobody is not on the list

No. in looks at keys only. Checking for a value takes a loop.

Chunk 5 of 8

Looping over a dictionary

A for loop over a dictionary gives you the keys, one at a time. Use the key to look up the value inside the loop.

scores = {"Ada": 16, "Grace": 22, "Alan": 9}
for name in scores:
    print(name, "->", scores[name])

total = 0
for name in scores:
    total = total + scores[name]
print("total points:", total)

Predict: The loop variable is called name. Does it hold a key or a value?

What it actually prints

Ada -> 16
Grace -> 22
Alan -> 9
total points: 47

A key. The value needs a lookup. The second loop is session 3's accumulator with a dictionary behind it, unchanged in every other respect.

Chunk 6 of 8

A tally: counting with a dictionary

Counting how often each thing appears is what dictionaries are best at. Start with an empty dictionary. For each item, either add one to what is there or start it at one.

message = "MEET AT NOON"
counts = {}
for ch in message:
    if ch in counts:
        counts[ch] = counts[ch] + 1
    else:
        counts[ch] = 1
print(counts)
print("Es:", counts["E"], " Os:", counts["O"], " spaces:", counts[" "])

Predict: The gate has two branches. Which one runs the first time a letter is seen?

What it actually prints

{'M': 1, 'E': 2, 'T': 2, ' ': 2, 'A': 1, 'N': 2, 'O': 2}
Es: 2  Os: 2  spaces: 2

The else branch, because the key is not there yet. Every count in the dictionary was created in that branch. Without the gate you get a KeyError on the very first letter.

Chunk 7 of 8

Counts as a picture

A star for each count turns the dictionary into a display you can read at a glance. Multiplying a string by a number repeats it, which is the only new piece of syntax in this chunk.

message = "MEET AT NOON"
counts = {}
for ch in message:
    if ch in counts:
        counts[ch] = counts[ch] + 1
    else:
        counts[ch] = 1

for ch in counts:
    print(ch, "*" * counts[ch], counts[ch])

Predict: Which character has the longest bar, and is it a letter?

What it actually prints

M * 1
E ** 2
T ** 2
  ** 2
A * 1
N ** 2
O ** 2

The letters E, O and T tie at 2, and so does the space. In a longer message the space has the longest bar by far, and that is the first thing a code breaker looks for.

Chunk 8 of 8

A codebook is a dictionary

A codebook is a table of swaps for writing a secret message: wherever the message has an A, write this symbol in its place, and so on. A dictionary stores one directly, with the letter as the key and its symbol as the value, and the swaps do not have to follow any pattern at all. The gate handles characters the book does not cover.

book = {"A": "%", "E": "#", "M": "@", "N": "+", "O": "0", "T": "~"}

def encode(text):
    out = ""
    for ch in text:
        if ch in book:
            out = out + book[ch]
        else:
            out = out + ch
    return out

print(encode("MEET AT NOON"))

Predict: The book has six letters in it. What happens to the others?

What it actually prints

@##~ %~ +00+

They pass through untouched, which is why the output still looks like the original in places. A real codebook covers all 26, and building the reverse book to decode it is the stretch exit.

Before you build

Question: From session 5: write tally(text) as a function that returns a dictionary of counts. Then say what you would have to write instead if functions could not return values.

def tally(text):
    counts = {}
    for ch in text:
        if ch in counts:
            counts[ch] = counts[ch] + 1
        else:
            counts[ch] = 1
    return counts

result = tally("MEET AT NOON")
print(result)

def tally(text): with the loop from chunk 6 and return counts at the end. Without return you would have to print the counts and read them yourself, or keep the dictionary as one shared name outside the function, which is the arrangement that makes a program impossible to test.
