Code constraints

What this course uses, what it leaves out, and the one frame loop. Every page on this site obeys this list. Changing the list means republishing it with a new date.

Still excluded, all twelve sessions

  • Nested gates. Flat if, elif, else only. If a student reaches for an if inside an if, hand them and.
  • break and continue. Every while names its exit condition in the condition itself.
  • while True. Same reason.
  • try and except. Ask-until-valid loops cover the same ground at this level.
  • //. A single slash and % are enough.
  • class. Advanced course material.
  • Recursion, list comprehensions, lambda, global.
  • Multi-file programs and importing your own module. Advanced course.
  • File input and output. Held as a float, not in the spine.
  • pygame.font. Words go in the terminal and visuals go in the window. That split holds all term.
  • turtle. Not used anywhere in this course. It needs a library our VS Code setup does not have, so pygame does all of the drawing, starting in session 5. Any summer turtle asset stays out of this repo.

The frame loop, and only this one

Two idioms were in circulation across the summer projects. One used a frame counter with break, which is excluded here and silently capped runs at sixty seconds. This course uses the other one, everywhere, with no exceptions. Students first copy it in session 5 as a harness holding a finished drawing on screen, and session 10 takes it apart.

running = 1
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = 0
    screen.fill(BG)
    # draw here
    pygame.display.flip()
    clock.tick(60)
pygame.quit()

A window never closes itself. It closes when the person closes it. Any summer asset brought into this course gets normalised to this shape before it is handed out.

Two placements of the drawing, both legitimate, and students meet them in this order. In session 5 the drawing is done once onto a pygame.Surface above the loop, and the loop only blits it, because the picture never changes. From session 10 on, the fill and the drawing sit inside the loop, because the picture changes every frame.

Standing rules

  • One change per run. Change one thing, run it, write down what happened.
  • Predict before you run. Out loud or on paper, every chunk.
  • Expected and got. The expected column is filled in before the run, not after.
  • Honest names. A function called check that removes a life gets renamed. This is an exit criterion, not a style preference.
  • Words in the terminal, visuals in the window.
  • Knob block at the top. Every number the behaviour depends on gets a capitalised name above the code that uses it.

Verification

Every output box on every session page was produced by running that exact snippet, not typed from expectation. Terminal snippets were run with real input where they ask for it. The pygame snippets were run without a screen, with a quit event injected after a set number of frames, and the printed probe lines on those pages are the real ones. Every snippet on this site was run. Where a snippet continues a program from an earlier chunk, the page says so and the whole file was run together.
