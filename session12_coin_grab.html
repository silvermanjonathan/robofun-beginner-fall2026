Chunk 1 of 4

A Rect is four numbers with names

In session 6 a rectangle was four numbers in parentheses: x, y, width, and height. pygame.Rect keeps those four numbers together under one name. It is written with a capital R. A Rect also works out its own edges. left is x, and right is x plus the width. top is y, and bottom is y plus the height. center is the pair of numbers in the middle of the rectangle; pygame spells it with er at the end.

This program opens no window. A Rect is only numbers, so the terminal can print them.

import pygame

coin = pygame.Rect(300, 200, 30, 30)
print(coin.left, coin.right)
print(coin.top, coin.bottom)
print(coin.center)

Predict: The coin starts 300 across and is 30 wide. What does coin.right print? The coin starts 200 down and is 30 tall. What does coin.bottom print?

What it actually prints

300 330
200 230
(315, 215)

The first one: 330, because 300 + 30 is 330. The second one: 230, because 200 + 30 is 230. The last line prints the middle of the coin. Half of 30 is 15, and 15 across and 15 down from the corner at 300, 200 is (315, 215).

Chunk 2 of 4

Are two rectangles touching? The test, written by hand

Two rectangles are touching when they overlap: part of one is on top of part of the other. Checking that takes two tests. Across: each rectangle starts before the other one ends, so its left is less than the other one's right. Down: the same test with top and bottom. Both tests have to be True, and and joins them.

The player here is a square from 280 to 330 across and from 190 to 240 down. The coin starts below it. Then coin.y = 200 moves the coin up, and the down test is worked out again.

import pygame

player = pygame.Rect(280, 190, 50, 50)
coin = pygame.Rect(300, 280, 30, 30)

across = player.left < coin.right and coin.left < player.right
down = player.top < coin.bottom and coin.top < player.bottom
print(f"across {across}, down {down}, touching {across and down}")

coin.y = 200
down = player.top < coin.bottom and coin.top < player.bottom
print(f"across {across}, down {down}, touching {across and down}")

Predict: The first print runs with the coin at y = 280. Will across be True or False, and will down be True or False? Then say what changes in the second print, after the coin has moved to y = 200.

What it actually prints

across True, down False, touching False
across True, down True, touching True

The first one: across is True. The player goes from 280 to 330 and the coin from 300 to 330, so each one starts before the other ends. down is False. The player ends at 240 and the coin starts at 280, so coin.top < player.bottom is False. Being lined up across is not enough, so touching is False.

The second one: at y = 200 the coin goes from 200 to 230 down, which is inside the player's 190 to 240. Now down is True, and touching is True.

Chunk 3 of 4

colliderect asks the same question in one call

A Rect can make that whole test itself. player.colliderect(coin) gives True when the two rectangles overlap and False when they do not. It is chunk 2's test, already written for you. The name is two words joined: collide, which means to bump into something, and rect.

This program asks the question three times. The first time, the coin is where chunk 2 left it, inside the player. Before the second and third times, it moves the coin by changing coin.x.

import pygame

coin = pygame.Rect(300, 200, 30, 30)
print(player.colliderect(coin))

coin.x = 330
print(player.colliderect(coin))

coin.x = 329
print(player.colliderect(coin))

Predict: The player's right edge is at 330. The line coin.x = 330 puts the coin's left edge at 330 too, so the two rectangles share an edge. Will the second print say True or False? And the third print, with the coin one pixel further left?

What it actually prints

True

The first one: False. Chunk 2's test is coin.left < player.right, and 330 is not less than 330. Sharing an edge is not overlapping. The second one: True. At 329 the coin's left edge is one pixel inside the player, and one pixel is enough.

Chunk 4 of 4

A square that follows the mouse

This is the first window of the day. Most of it is the knob block and the frame loop from session 11, and three lines are new.

The line player = pygame.Rect(0, 0, PLAYER_SIZE, PLAYER_SIZE) makes the player, a Rect 50 across and 50 down. It is above the loop, so it runs once.

The line player.center = pygame.mouse.get_pos() is inside the loop, so it runs on every frame. pygame.mouse.get_pos() gives the position of the mouse in the window as a pair of numbers, across and then down. Storing that pair in player.center moves the whole square, so that its middle is on the mouse.

The line pygame.draw.rect(screen, PLAYER, player) draws the square. In session 6 the third thing given to draw.rect was four numbers in parentheses. A Rect works in the same place.

The last print runs when you close the window.

import pygame

# ---- knob block: every number the game depends on ----
WIDTH = 600
HEIGHT = 400
PLAYER_SIZE = 50
BG = (27, 41, 81)
PLAYER = (248, 250, 252)
FPS = 60

pygame.init()
screen = pygame.display.set_mode((WIDTH, HEIGHT))
clock = pygame.time.Clock()

player = pygame.Rect(0, 0, PLAYER_SIZE, PLAYER_SIZE)

running = 1
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = 0

    player.center = pygame.mouse.get_pos()

    screen.fill(BG)
    pygame.draw.rect(screen, PLAYER, player)
    pygame.display.flip()
    clock.tick(FPS)

print(f"centre {player.center}, left {player.left}, top {player.top}")
pygame.quit()

left is 275 and top is 175. Half of 50 is 25, so the left edge is 25 to the left of the mouse and the top edge is 25 above it.

The run on this page had no real mouse. It was given a mouse position of (300, 200). Your numbers depend on where your mouse is when you close the window, so they will be different. If your square sits in the top left corner and does not move, the mouse is outside the window.

Build: coin grab

You are making a small game called coin grab. A white square follows the mouse. A gold coin sits in the window. When the square touches the coin, the coin jumps to a new spot picked at random, and the terminal counts it. Ten coins wins the game. The build is one program, written in three tools. Each tool starts from the program the tool before it finished.

  1. Start from chunk 4's file, Jonathan_session12.py with your first name in place of Jonathan: the square that follows the mouse.
  2. Add a coin, and make it jump to a random spot when the player touches it.
  3. Add a score that goes up by 1 for each coin, printed in the terminal.
  4. End the game at ten coins: the window turns green and the coin stops jumping.
  5. Put three coins in a list, and add a 30 second time limit that turns the window red.

import random
import pygame

# ---- knob block: every number the game depends on ----
WIDTH = 600
HEIGHT = 400
PLAYER_SIZE = 50
COIN_SIZE = 30
BG = (27, 41, 81)
PLAYER = (248, 250, 252)
COIN = (252, 211, 77)
FPS = 60

pygame.init()
screen = pygame.display.set_mode((WIDTH, HEIGHT))
clock = pygame.time.Clock()

player = pygame.Rect(0, 0, PLAYER_SIZE, PLAYER_SIZE)
coin = pygame.Rect(300, 200, COIN_SIZE, COIN_SIZE)

running = 1
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = 0

    player.center = pygame.mouse.get_pos()
    if player.colliderect(coin):
        coin.x = random.randint(0, WIDTH - COIN_SIZE)
        coin.y = random.randint(0, HEIGHT - COIN_SIZE)
        print(f"grabbed, the coin is now at {coin.x}, {coin.y}")

    screen.fill(BG)
    pygame.draw.rect(screen, COIN, coin)
    pygame.draw.rect(screen, PLAYER, player)
    pygame.display.flip()
    clock.tick(FPS)

print(f"centre {player.center}, left {player.left}, top {player.top}")
pygame.quit()

import random
import pygame

# ---- knob block: every number the game depends on ----
WIDTH = 600
HEIGHT = 400
PLAYER_SIZE = 50
COIN_SIZE = 30
GOAL = 10
BG = (27, 41, 81)
PLAYER = (248, 250, 252)
COIN = (252, 211, 77)
WIN = (29, 91, 57)
FPS = 60

pygame.init()
screen = pygame.display.set_mode((WIDTH, HEIGHT))
clock = pygame.time.Clock()

player = pygame.Rect(0, 0, PLAYER_SIZE, PLAYER_SIZE)
coin = pygame.Rect(300, 200, COIN_SIZE, COIN_SIZE)

score = 0
playing = 1
background = BG

running = 1
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = 0

    player.center = pygame.mouse.get_pos()
    if playing == 1 and player.colliderect(coin):
        coin.x = random.randint(0, WIDTH - COIN_SIZE)
        coin.y = random.randint(0, HEIGHT - COIN_SIZE)
        score = score + 1
        print(f"score {score}")
    if playing == 1 and score >= GOAL:
        playing = 0
        background = WIN
        print(f"You win with {score} coins.")

    screen.fill(background)
    pygame.draw.rect(screen, COIN, coin)
    pygame.draw.rect(screen, PLAYER, player)
    pygame.display.flip()
    clock.tick(FPS)

print(f"final score {score}")
pygame.quit()

Tool 3: three coins in a list, and a time limit

One coin is slow. Now there are three, kept in a list, and a loop asks the touching question once for each coin. There is also a time limit. The frame loop runs 60 times a second, so counting frames is counting time: when the counter reaches 30 seconds of frames and the player has not won, the window turns red and the game is over.

import random
import pygame

# ---- knob block: every number the game depends on ----
WIDTH = 600
HEIGHT = 400
PLAYER_SIZE = 50
COIN_SIZE = 30
GOAL = 10
BG = (27, 41, 81)
PLAYER = (248, 250, 252)
COIN = (252, 211, 77)
WIN = (29, 91, 57)
FPS = 60

pygame.init()
screen = pygame.display.set_mode((WIDTH, HEIGHT))
clock = pygame.time.Clock()

player = pygame.Rect(0, 0, PLAYER_SIZE, PLAYER_SIZE)
coin = pygame.Rect(300, 200, COIN_SIZE, COIN_SIZE)

score = 0
playing = 1
background = BG

running = 1

            running = 0

        coin.y = random.randint(0, HEIGHT - COIN_SIZE)
        score = score + 1
        print(f"score {score}")
    if playing == 1 and score >= GOAL:
        playing = 0
        background = WIN
        print(f"You win with {score} coins.")

    screen.fill(background)
    pygame.draw.rect(screen, COIN, coin)
    pygame.draw.rect(screen, PLAYER, player)
    pygame.display.flip()

import random
import pygame

# ---- knob block: every number the game depends on ----
WIDTH = 600
HEIGHT = 400
PLAYER_SIZE = 50
COIN_SIZE = 30
GOAL = 10
SECONDS = 30
BG = (27, 41, 81)
PLAYER = (248, 250, 252)
COIN = (252, 211, 77)
WIN = (29, 91, 57)
LOSE = (156, 43, 34)
FPS = 60

pygame.init()
screen = pygame.display.set_mode((WIDTH, HEIGHT))
clock = pygame.time.Clock()

player = pygame.Rect(0, 0, PLAYER_SIZE, PLAYER_SIZE)
coins = [
    pygame.Rect(100, 100, COIN_SIZE, COIN_SIZE),
    pygame.Rect(300, 200, COIN_SIZE, COIN_SIZE),
    pygame.Rect(500, 300, COIN_SIZE, COIN_SIZE),
]

score = 0
playing = 1
background = BG
frame = 0

running = 1
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = 0

    player.center = pygame.mouse.get_pos()
    frame = frame + 1
    for coin in coins:
        if playing == 1 and player.colliderect(coin):
            coin.x = random.randint(0, WIDTH - COIN_SIZE)
            coin.y = random.randint(0, HEIGHT - COIN_SIZE)
            score = score + 1
            print(f"score {score}")
    if playing == 1 and score >= GOAL:
        playing = 0
        background = WIN
        print(f"You win with {score} coins.")
    if playing == 1 and frame == SECONDS * FPS:
        playing = 0
        background = LOSE
        print(f"Time is up. You got {score} coins.")

    screen.fill(background)
    for coin in coins:
        pygame.draw.rect(screen, COIN, coin)
    pygame.draw.rect(screen, PLAYER, player)
    pygame.display.flip()
    clock.tick(FPS)

print(f"final score {score}")
pygame.quit()

Give the jump a name

The two randint lines move a coin to a random spot. A function can hold them, so the game can move a coin from more than one place. Then every game can start with its coins in different spots.

move_coin changes the Rect it is given

This function has one parameter, coin, and no return line. It does not work out a value. It changes the Rect that the call gives it. The program prints where the coin is, calls the function, and prints where the coin is again. The last line prints what the function returns.

import random
import pygame

WIDTH = 600
HEIGHT = 400
COIN_SIZE = 30

def move_coin(coin):
    coin.x = random.randint(0, WIDTH - COIN_SIZE)
    coin.y = random.randint(0, HEIGHT - COIN_SIZE)

coin = pygame.Rect(300, 200, COIN_SIZE, COIN_SIZE)
print(coin.x, coin.y)

move_coin(coin)
print(coin.x, coin.y)

print(move_coin(coin))

Predict: The function has no return line. What does the last line print? And does the coin move when the function is called?

The first one: the last line prints None. A function with no return line returns None, the same as in session 5. The second one: yes, the coin moves. The first print says 300 200 and the second says 57 46, so the call move_coin(coin) changed the Rect it was given. The last line calls the function a second time, so the coin moves once more before None is printed. The spots are picked at random, so your numbers will be different.

Running this in VS Code

Once, before the first run

Open the terminal in VS Code and install the library: pip install pygame. Check it worked with python -c "import pygame". It should print two lines of greeting from pygame and nothing else. A traceback here is an install problem, not a problem with your program. Those same two greeting lines appear at the top of the terminal every time you run a pygame program; the output boxes on this site leave them out.

Every run after that

The window often opens behind VS Code, so check the taskbar before deciding nothing happened. Close it with its own close button: these programs are written to end when the window closes, and stopping the terminal instead can leave the window stuck on screen. A window that will not close usually means the loop has no pygame.event.get() in it.

There is no turtle anywhere in this course. Turtle needs a library our VS Code setup does not have, so pygame does all the drawing, starting in session 6.
