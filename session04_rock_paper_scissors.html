Opener · 10 minutes

Question: Write the line that makes a list called moves holding rock, paper, and scissors, then the line that picks one item from it at random and stores it under the name computer. What has to be at the top of the file for the second line to work?

import random

moves = ["rock", "paper", "scissors"]
computer = random.choice(moves)

import random at the top of the file. random.choice takes a list and gives back one of its items. Without the import line, Python does not know the name random and stops with a NameError.

Question: When is the condition you == "rock" and computer == "scissors" True? Say what each side has to be.

Only when both comparisons are True: you holds the text rock and computer holds the text scissors. If either side is False, and makes the whole condition False. That is the test for one way to win at rock paper scissors, and today it goes in a gate.

Chunk 1 of 8

The computer picks a move

The three moves live in one list. random.choice picks one item from it, and the f-string prints which one. Run this three times before you go on.

import random

moves = ["rock", "paper", "scissors"]
computer = random.choice(moves)
print(f"The computer picked {computer}.")

Predict: random.choice picks from the list. Can it ever pick something that is not in the list, and do three runs give the same move?

What it actually prints, on one run

The computer picked scissors.

No, and usually not. The first answer: it only ever gives back one of the three items, so computer is always rock, paper, or scissors, spelled exactly as the list spells it. The second answer: there is no random.seed line, so each run picks afresh, and three runs match only by chance, the way three coin flips can. The output box shows one run, and your runs do not have to match it. The move that can be anything is the one the player is about to type.

Chunk 2 of 8

Your move comes from the keyboard

input gives you the text the player typed. A tie is the easiest result to test for, so the gate starts there: one comparison between the typed move and the picked move.

import random

moves = ["rock", "paper", "scissors"]
computer = random.choice(moves)
you = input("rock, paper, or scissors: ")
print(f"You picked {you}. The computer picked {computer}.")
if you == computer:
    print("Tie.")
else:
    print("Not a tie.")

Predict: You type rock and the computer picks rock. you came from the keyboard and computer came from the list. Does == say they are the same?

What it actually prints, on one run

rock, paper, or scissors: rock
You picked rock. The computer picked rock.
Tie.

Yes. Both variables hold the same four characters, r o c k, and == compares the characters. It does not care whether a value was typed, picked from a list, or written in the code. The quote marks around rock in the list are not part of the value. Type Rock with a capital R and the gate prints Not a tie, because R and r are different characters.

Chunk 3 of 8

One way to win, and a gate that is wrong

Rock beats scissors. Here that one rule becomes an elif with and, under the tie test, and the else prints that the computer won.

Line 6 is a probe: a print whose only job is to show you a value the program would otherwise keep to itself. Without it you would not know what the computer picked, so you could not tell whether the gate got the round right. Keep it in while you build, and take it out when the game works.

import random

moves = ["rock", "paper", "scissors"]
computer = random.choice(moves)
you = input("rock, paper, or scissors: ")
print(f"You picked {you}. The computer picked {computer}.")
if you == computer:
    print("Tie.")
elif you == "rock" and computer == "scissors":
    print("You win.")
else:
    print("The computer wins.")

Predict: You type paper and the computer picks rock. Paper beats rock. Which of the three print lines runs, and is it right?

What it actually prints, on one run

rock, paper, or scissors: paper
You picked paper. The computer picked rock.
The computer wins.

The last print line runs, and it is wrong: the output says the computer wins, and paper beats rock. The if is False, because paper and rock are different. The elif is False, because you did not type rock. So Python runs the else, which is every case the lines above it did not name, and right now that includes two winning pairs. No error appears. The program runs to the end and prints the wrong answer, which is a silent bug: the probe on line 6 is the only reason you can see it.

Chunk 5 of 8

Rounds: the game inside a for loop

One round is a pick, a question, and the gate. For three rounds, put those lines inside a for loop with range(1, 4), and print the round number at the top of each pass. Every line that belongs to a round moves right by four spaces, so the gate's if, elif, and else lines now start four spaces in, and their print lines start eight spaces in.

The import and the list stay above the loop. The list is made once and used on every pass.

import random

moves = ["rock", "paper", "scissors"]

for round_number in range(1, 4):
    print(f"Round {round_number}")
    computer = random.choice(moves)
    you = input("rock, paper, or scissors: ")
    print(f"You picked {you}. The computer picked {computer}.")
    if you == computer:
        print("Tie.")
    elif you == "rock" and computer == "scissors":
        print("You win.")
    elif you == "paper" and computer == "rock":
        print("You win.")
    elif you == "scissors" and computer == "paper":
        print("You win.")
    else:
        print("The computer wins.")

Chunk 6 of 8

Two counters keep the score

A counter is a variable the program adds 1 to. Two of them, started at 0 above the loop: your_wins adds 1 in each of the three win branches, and computer_wins adds 1 in the else. The tie branch adds to neither. After the loop, one f-string prints both.

import random

moves = ["rock", "paper", "scissors"]
your_wins = 0
computer_wins = 0

for round_number in range(1, 4):
    print(f"Round {round_number}")
    computer = random.choice(moves)
    you = input("rock, paper, or scissors: ")
    print(f"You picked {you}. The computer picked {computer}.")
    if you == computer:
        print("Tie.")
    elif you == "rock" and computer == "scissors":
        print("You win.")
        your_wins = your_wins + 1
    elif you == "paper" and computer == "rock":
        print("You win.")
        your_wins = your_wins + 1
    elif you == "scissors" and computer == "paper":
        print("You win.")
        your_wins = your_wins + 1
    else:
        print("The computer wins.")
        computer_wins = computer_wins + 1

print(f"You won {your_wins}. The computer won {computer_wins}.")

Chunk 8 of 8

Ask until the move is on the list

Type a move with a typo, say rokc, and the program counts it as a loss: the tie test is False, no elif matches, and the else runs. No error, wrong answer, a silent bug.

The fix is the asking loop from session 2, placed inside the for loop where the input line was. The stopping condition has three tests joined by and: keep asking while the answer is not rock and not paper and not scissors. you = "" goes just above it, so the condition has a value to test on its first check. This is the whole program, with the verdict from chunk 7 at the bottom.

import random

moves = ["rock", "paper", "scissors"]
your_wins = 0
computer_wins = 0

for round_number in range(1, 4):
    print(f"Round {round_number}")
    computer = random.choice(moves)
    you = ""
    while you != "rock" and you != "paper" and you != "scissors":
        you = input("rock, paper, or scissors: ")
    print(f"You picked {you}. The computer picked {computer}.")
    if you == computer:
        print("Tie.")
    elif you == "rock" and computer == "scissors":
        print("You win.")
        your_wins = your_wins + 1
    elif you == "paper" and computer == "rock":
        print("You win.")
        your_wins = your_wins + 1
    elif you == "scissors" and computer == "paper":
        print("You win.")
        your_wins = your_wins + 1
    else:
        print("The computer wins.")
        computer_wins = computer_wins + 1

print(f"You won {your_wins}. The computer won {computer_wins}.")
if your_wins > computer_wins:
    print("You win the match.")
elif your_wins == computer_wins:
    print("The match is a tie.")
else:
    print("The computer wins the match.")

Question: From session 2: a student writes the asking loop with or in place of each and, as below. The player types rock. Which of the three tests are True for rock, and does the loop stop?

you = ""

Two of the three tests are True: rock is not paper, and rock is not scissors. Only you != "rock" is False. With or, one True is enough to make the whole condition True, so the loop asks again, and it does the same for paper and for scissors. It never stops. Build · 15 minutes

Build: first to three

You are writing a game for someone else to play. The person at the keyboard is the player, and the program is the opponent. In chunk 8 the game lasts exactly three rounds. In this version it lasts until someone has won three rounds, which could take three rounds or thirty. A for loop with range has to be told how many passes to make, so it does not fit. A while loop fits: it keeps going while neither counter has reached 3.

  1. Start from the chunk 8 program. Add a third counter, ties, started at 0 above the loop and adding 1 in the tie branch.
  2. Replace the for line with while your_wins < 3 and computer_wins < 3:. The lines under it stay exactly as they are.
  3. range no longer counts the rounds for you, so make round_number = 0 above the loop and add 1 to it as the first line inside the loop, before the line that prints the round.
  4. After the loop, print all three counters and the round count in one f-string.
  5. Print who won the match. There are only two ways out of the loop now, so write the gate with two branches, and say to the person next to you why the tie branch is gone.

Extension · for after the stretch exit

Extension: rock paper scissors lizard Spock

The same game with five moves instead of three. It was invented by Sam Kass and Karen Bryla, and the point of it is that ties happen less often: with three moves, one pair in three is a tie, and with five moves it is one pair in five. Each move beats two of the other four.

MoveBeats these two
rockscissors, lizard
paperrock, spock
scissorspaper, lizard
lizardspock, paper
spockscissors, rock

Three things change in the chunk 8 program, and the loops do not. The list gets two more items, in lowercase so the player types them the same way as the others. The asking loop gets two more tests, one per new move, joined with and like the first three. The gate gets one win branch per move instead of one per rule.

A move now beats two moves, so each win branch names both of them, with or between them and parentheses around the pair. Python works out what is inside the parentheses first, the same as in maths: computer == "scissors" or computer == "lizard" comes out True or False, and then and joins that answer to you == "rock". You could write ten elif lines instead, one per way to win, and that works too. This version has five.

The whole program with five moves

The computer picks at random, so your run will be different from the one in the box.

import random

moves = ["rock", "paper", "scissors", "lizard", "spock"]
your_wins = 0
computer_wins = 0

for round_number in range(1, 4):
    print(f"Round {round_number}")
    computer = random.choice(moves)
    you = ""
    while you != "rock" and you != "paper" and you != "scissors" and you != "lizard" and you != "spock":
        you = input("rock, paper, scissors, lizard, or spock: ")
    print(f"You picked {you}. The computer picked {computer}.")
    if you == computer:
        print("Tie.")
    elif you == "rock" and (computer == "scissors" or computer == "lizard"):
        print("You win.")
        your_wins = your_wins + 1
    elif you == "paper" and (computer == "rock" or computer == "spock"):
        print("You win.")
        your_wins = your_wins + 1
    elif you == "scissors" and (computer == "paper" or computer == "lizard"):
        print("You win.")
        your_wins = your_wins + 1
    elif you == "lizard" and (computer == "spock" or computer == "paper"):
        print("You win.")
        your_wins = your_wins + 1
    elif you == "spock" and (computer == "scissors" or computer == "rock"):
        print("You win.")
        your_wins = your_wins + 1
    else:
        print("The computer wins.")
        computer_wins = computer_wins + 1

print(f"You won {your_wins}. The computer won {computer_wins}.")
if your_wins > computer_wins:
    print("You win the match.")
elif your_wins == computer_wins:
    print("The match is a tie.")
else:
    print("The computer wins the match.")

Building it

  1. Add "lizard" and "spock" to the move list. random.choice needs no change, because the list is the one place the moves live.
  2. Add two tests to the asking loop's stopping condition, one for each new move, each joined with and. Change the question so it names all five moves.
  3. Replace the three win branches with five, one per move. Each one names the two moves it beats inside parentheses with or between them. Use the table.
  4. Keep the tie branch first and the else last. Nothing else in the gate changes.
  5. Test one pair from each row of the table, both ways round: lizard against paper should print You win, and paper against lizard should print The computer wins.
