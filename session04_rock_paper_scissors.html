Extension · for after the stretch exit

Extension: rock paper scissors lizard Spock

The same game with five moves instead of three. It was invented by Sam Kass and Karen Bryla, and the point of it is that ties happen less often: with three moves, one pair in three is a tie, and with five moves it is one pair in five. Each move beats two of the other four and loses to the other two, so the arrows still balance and no move is the best one to pick.

MoveBeats these two
rockscissors, lizard

scissorspaper, lizard
lizardspock, paper
spockscissors, rock

Three things change in the chunk 8 program, and the loops do not. The list gets two more items, in lowercase so the player types them the same way as the others. The asking loop gets two more tests, one per new move, joined with and like the first three. The gate gets one win branch per move instead of one per arrow.

A move now beats two moves, so each win branch names both of them, with or between them and parentheses around the pair. Python works out what is inside the parentheses first, the same as in maths: computer == "scissors" or computer == "lizard" comes out True or False, and then and joins that answer to you == "rock". You could write ten elif lines instead, one per arrow, and that works too. This version has five.

  1. Add "lizard" and "spock" to the move list. random.choice needs no change, because the list is the one place the moves live.
  2. Add two tests to the asking loop's stopping condition, one for each new move, each joined with and. Change the question so it names all five moves.
  3. Replace the three win branches with five, one per move. Each one names the two moves it beats inside parentheses with or between them. Read the two arrows that leave each move.
  4. Keep the tie branch first and the else last. Nothing else in the gate changes.
  5. Test one arrow from each move, both ways round: lizard against paper should print You win, and paper against lizard should print The computer wins.

What you will see, and what to do

In the roomRedirect
Types Rock with a capital letter, gets asked again, and says the program is broken.It is not. == compares every character, and R is not r. Have them type it in lowercase. Session 7 teaches lower, which fixes this for good; do not teach it today.
Writes or between the three tests in the asking loop and the program asks forever.Substitute rock into all three tests out loud. Two stay True, and or needs only one. This is the hinge question. If it happens before the hinge, let the room watch, and stop the program with Ctrl+C in the terminal.
Writes you == "rock" and "scissors", and rock now beats paper.Each side of and has to be a whole comparison. The right side here is the text scissors on its own, which Python treats as True, so the branch runs whenever the player typed rock and the round was not a tie. Print the two halves separately and ask what the second one is.
Puts your_wins = 0 inside the loop and the scoreboard never gets past 1.Session 3's accumulator bug in a new place. The scoreboard line already shows it resetting; ask them to read the score after each round out loud.
Adds an elif for each way to lose, or a second tie test.Both run and both are correct, so do not call it wrong. Count the nine pairs on the table together and ask which ones are left when the else is reached. The three losses are, so the else is enough.
Answers a What goes next? question with the right idea in the wrong words, for example a loop that asks again, without naming while.Take the idea and ask for the line. Hint 2 names the construct and hint 3 shows it with a blank, so open them in that order rather than saying the answer.
Cannot stop a loop that never ends.Ctrl+C in the terminal. Teach it the first time it happens and not before.

If time runs out

If the room is slow, stop after chunk 6 and make the build the three-round game with the scoreboard; that is a real middle exit, and chunks 7 and 8 fit in the first fifteen minutes of session 5 as retrieval. If the room is fast, the extension is twenty minutes of work and needs nothing from you after the arrows are read out once. The one new piece of punctuation in it is the parentheses, and without them the win branches give the wrong answer with no error: you == "rock" and computer == "scissors" or computer == "lizard" is True for every pick of lizard, because Python reads the and first. Let a student find that before you say it.
