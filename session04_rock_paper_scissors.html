Two of the three tests are True: rock is not paper, and rock is not scissors. Only you != "rock" is False. Build · 15 minutes

Build: first to three

You are writing a game for someone else to play. The person at the keyboard is the player, and the program is the opponent. In chunk 8 the game lasts exactly three rounds. In this version it lasts until someone has won three rounds, which could take three rounds or thirty. A for loop with range has to be told how many passes to make, so it does not fit. A while loop fits: it keeps going while neither counter has reached 3.

  1. Start from the chunk 8 program. Add a third counter, ties, started at 0 above the loop and adding 1 in the tie branch. Put it on the score line too.
  2. Replace the for line with while your_wins < 3 and computer_wins < 3:. The lines under it stay exactly as they are.

Extension · for after the stretch exit

Extension: rock paper scissors lizard Spock

The same game with five moves instead of three. Sam Kass and Karen Bryla invented it so that ties happen less often: with three moves, one pair in three is a tie, and with five moves it is one pair in five. Each move beats two of the other four and loses to the other two, so no move is better than the others.

The ten rules as arrows

MoveBeats these two

Three things change in the chunk 8 program. The loops do not change. The list gets two more items, in lowercase, so the player types them the same way as the others. The asking loop gets two more tests, one per new move, joined with and like the first three. The gate gets one win branch per move instead of one per arrow.

A move now beats two moves, so each win branch names both of them, with or between them and parentheses around the pair. Python works out what is inside the parentheses first, the same as in math: computer == "scissors" or computer == "lizard" comes out True or False, and then and joins that answer to you == "rock". You could write ten elif lines instead, one per arrow, and that works too. This version has five.
