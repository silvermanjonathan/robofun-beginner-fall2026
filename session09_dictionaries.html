Chunk 1 of 8

Two lists that have to stay lined up

This is how you have stored paired information so far. It works right up until the two lists stop matching, and then it keeps working while being wrong.

names = ["Ada", "Grace", "Alan"]
scores = [15, 22, 9]
print(names[1], "has", scores[1], "points")

names = ["Ada", "Zoe", "Grace", "Alan"]
print(names[1], "has", scores[1], "points")

Predict: A new rider is added to the names list only. What does the second print say?

That Zoe has 22 points, which belong to Grace. No error, no warning. In a game with five parallel lists for position, speed, size and colour, one insert breaks everything and nothing tells you.

What actually happens

Grace has 22 points
Zoe has 22 points

Chunk 2 of 8

A dictionary pairs a key with a value

Curly braces, and a colon between each key and its value. Look a value up by writing the key in square brackets. There are no slot numbers here and no order to keep in step.

scores = {"Ada": 15, "Grace": 22, "Alan": 9}
print(scores["Grace"])
print(len(scores))

Predict: You look up Grace by name rather than by number. What happens to the pairing problem from chunk 1?

It is gone. The name and the score are stored together, so there is no second list to keep lined up. Each key holds exactly one value, which is the same rule as a function from session 4: one input, one output.

What actually happens

22
3

Chunk 3 of 8

Add, change, and ask for something that is not there

Assigning to a key that exists changes it. Assigning to a key that does not exist creates it. Looking up a key that does not exist is an error with its own name.

scores = {"Ada": 15, "Grace": 22}
scores["Ada"] = 16
scores["Katherine"] = 30
print(scores)
print(scores["Nobody"])

Predict: Same line shape for changing Ada and for adding Katherine. How does Python know which one you meant?

It does not need to know. If the key is there it is replaced, and if it is not it is created. The last line is a KeyError, which is number six on your error list.

What actually happens

{'Ada': 16, 'Grace': 22, 'Katherine': 30}
Traceback (most recent call last):
  File "session09.py", line 5, in <module>
    print(scores["Nobody"])
          ~~~~~~^^^^^^^^^^
KeyError: 'Nobody'

Chunk 4 of 8

in checks the keys, and gates against KeyError

in on a dictionary asks about keys, not values. This is the gate that stops the error from the last chunk.

scores = {"Ada": 16, "Grace": 22}
print("Ada" in scores)
print("Nobody" in scores)
print(16 in scores)

who = "Nobody"
if who in scores:
    print(who, "scored", scores[who])
else:
    print(who, "is not on the list")

Predict: Ada's score is 16. Does 16 in scores hand back True?

No. in looks at keys only. Checking for a value takes a loop, which tells you something about what a dictionary is fast at and what it is not.

What actually happens

True
False
False
Nobody is not on the list

Chunk 5 of 8

Looping over a dictionary

A for loop over a dictionary hands you the keys, one at a time. Use the key to look up the value inside the loop.

scores = {"Ada": 16, "Grace": 22, "Alan": 9}
for name in scores:
    print(name, "->", scores[name])

total = 0
for name in scores:
    total = total + scores[name]
print("total points:", total)

Predict: The loop variable is called name. Does it hold a key or a value?

A key. The value needs a lookup. The second loop is session 3's accumulator with a dictionary behind it, unchanged in every other respect.

What actually happens

Ada -> 16
Grace -> 22
Alan -> 9
total points: 47

Chunk 6 of 8

A tally: counting with a dictionary

Counting how often each thing appears is the job dictionaries are best at. Start with an empty dictionary. For each item, either add one to what is there or start it at one.

message = "MEET AT NOON"
counts = {}
for ch in message:
    if ch in counts:
        counts[ch] = counts[ch] + 1
    else:
        counts[ch] = 1
print(counts)
print("Es:", counts["E"], " Os:", counts["O"], " spaces:", counts[" "])

Predict: The gate has two branches. Which one runs the first time a letter is seen?

The else branch, because the key is not there yet. Every count in the dictionary started life in that branch. Without the gate you get a KeyError on the very first letter.

What actually happens

{'M': 1, 'E': 2, 'T': 2, ' ': 2, 'A': 1, 'N': 2, 'O': 2}
Es: 2  Os: 2  spaces: 2

Chunk 7 of 8

Counts as a picture

A star for each count turns the dictionary into a display you can read at a glance. Multiplying a string by a number repeats it, which is the only new piece of syntax in this chunk.

message = "MEET AT NOON"
counts = {}
for ch in message:
    if ch in counts:
        counts[ch] = counts[ch] + 1
    else:
        counts[ch] = 1

for ch in counts:
    print(ch, "*" * counts[ch], counts[ch])

Predict: Which character has the longest bar, and is it a letter?

The letters E, O and T tie at 2, and so does the space. In a longer message the space always wins by a wide margin, which is the first thing a code breaker notices.

What actually happens

M * 1
E ** 2
T ** 2
  ** 2
A * 1
N ** 2
O ** 2

Chunk 8 of 8

A codebook is a dictionary

Session 8 shifted letters by arithmetic. A codebook does it by lookup instead, which means the substitution does not have to follow any pattern at all. The gate handles characters the book does not cover.

book = {"A": "%", "E": "#", "M": "@", "N": "+", "O": "0", "T": "~"}

def encode(text):
    out = ""
    for ch in text:
        if ch in book:
            out = out + book[ch]
        else:
            out = out + ch
    return out

print(encode("MEET AT NOON"))

Predict: The book has six letters in it. What happens to the others?

They pass through untouched, which is why the output still looks like the original in places. A real codebook covers all 26, and building the reverse book to decode it is the stretch exit.

What actually happens

@##~ %~ +00+
