Opener · 10 minutes

Retrieval: two patterns from two weeks back

Paper. No editor until both are written.

Question: Write the accumulator that adds up a list called scores. Four lines.

total = 0, then for s in scores:, then total = total + s, then print(total).

Question: Where does total = 0 go, and what happens if it goes one line lower?

Above the loop. One line lower puts it inside the loop, which resets it every pass and prints the last item instead of the sum.

Chunk 1 of 7

Naming a block

def gives a name to a block of lines. Writing the name with parentheses after it, anywhere below, runs the block. This is new, and it is the half of today that has no trap in it.

def greet():
    print("Welcome to the park.")

greet()
greet()

Predict: How many lines of output, and does the def line itself print anything?

What it actually prints

Welcome to the park.
Welcome to the park.

Two lines. Defining a function does not run it. The block sits there until something calls it.

Chunk 2 of 7

Parameters let the caller fill in a blank

A name inside the parentheses is a blank the caller fills. Inside the block it behaves like any other name.

def greet(name):
    print(f"Welcome, {name}.")

greet("Ada")
greet("Grace")

Predict: Where does the value of name come from?

What it actually prints

Welcome, Ada.
Welcome, Grace.

From the call. It is different on each of the two calls, and it does not exist outside the function at all.

Chunk 3 of 7

return hands a value back to the caller

This is the new idea. return stops the function and hands a value back to whoever called it. The call itself becomes that value, which means you can store it, print it, or do arithmetic with it.

def double(n):
    return n * 2

answer = double(21)
print(answer)
print(double(5) + double(5))

Predict: Line 6 calls double twice and adds the results. Does that work?

What it actually prints

42
20

Yes. 42 and 20. Each call turns into its value, then the plus sign adds two ordinary numbers. A function that prints cannot do this, which is the next chunk.

Chunk 4 of 7

print and return are not the same thing

Two functions that look alike. One prints, one returns. Store the result of each and look at what you get.

def double_return(n):
    return n * 2

def double_print(n):
    print(n * 2)

a = double_return(21)
b = double_print(21)
print("a is", a)
print("b is", b)

Predict: Both functions do the same arithmetic. Will a and b hold the same value?

What it actually prints

42
a is 42
b is None

No. a holds 42. b holds None, which is Python's word for no value at all. A function with no return hands back None, every time. A function like double_print shows you a number and hands you nothing, which is why its output can be looked at but never used.

Chunk 5 of 7

One function calling another

Once a function hands back a value, another function can use it. Build small pieces and stack them. This is what people mean when they say a program is made of parts.

def area(w, h):
    return w * h

def floor_cost(w, h):
    return area(w, h) * 12

print(area(3, 4))
print(floor_cost(3, 4))

Predict: floor_cost never multiplies width by height itself. Does it still work?

What it actually prints

12
144

Yes. 12 and 144. floor_cost asks area for a number and then multiplies it by 12. Neither function knows or cares what the other one does inside.

Chunk 6 of 7

Several returns, gates still flat

A function can have more than one return. The first one reached wins and the function stops there, so a gate with three exits needs no else at the end.

def fare(age):
    if age < 5:
        return 0
    if age < 13:
        return 8
    return 12

print(fare(3))
print(fare(10))
print(fare(30))

Predict: fare(10) passes the second gate. Why does it not also reach the last line and come back as 12?

What it actually prints

0
8
12

Because return ends the function immediately. Nothing below it runs. 0, 8, 12. Three gates, no nesting, no else.

Chunk 7 of 7

Your accumulator, as a tool

Last session's four lines, wrapped in a name. Now it works on any list, and the answer comes back as a number you can use.

def total_of(numbers):
    total = 0
    for n in numbers:
        total = total + n
    return total

print(total_of([52, 47, 61]))
print(total_of([1, 2, 3, 4]))
print(total_of([52, 47, 61]) + total_of([1, 2, 3, 4]))

Predict: Where does return total have to sit, inside the loop or after it?

What it actually prints

160
10
170

After it, lined up with the for. Put it inside the loop and the function returns on the first pass with only the first number, which is a silent bug that gives you 52 instead of 160.

Hinge question · reaches back to session 2

Before you build

Question: From session 2: write a function called can_ride that takes a height and a ticket answer and hands back True or False. Use and. Then write the one line that uses it in a gate.

def can_ride(height, ticket):
    return height > 48 and ticket == "yes"

if can_ride(52, "yes"):
    print("Board the coaster.")

def can_ride(height, ticket): then return height > 48 and ticket == "yes". Used as if can_ride(52, "yes"):. Note that the comparison itself is already True or False, so it can be returned directly with no gate inside the function.

Build · 25 minutes

Build: three tools and one program that uses them

  1. Write total_of(numbers) that returns a sum.
  2. Write tallest_of(numbers) that returns the largest value, using best so far.
  3. Write average_of(numbers) that returns the mean, and make it call total_of rather than adding again.
  4. Make a list of heights and print all three results in one f-string.
  5. Check every one of your three tools against sum, max, and your own arithmetic.
